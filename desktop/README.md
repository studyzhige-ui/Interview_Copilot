# Windows 桌面应用使用帮助

桌面应用用于启动独立的本地 Docker 工作区。使用实际提供的 Windows x64 安装包时，请先确认其来源；GitHub Actions 中使用合成认证配置的验收安装包仅供测试，不能用于真实账号登录。

## 准备和启动

1. 自行安装并启动 Docker Desktop，切换到 Linux 容器。桌面应用不会代为安装 Docker 或修改 Windows 功能。
2. 安装并打开桌面应用。首次创建工作区前，可以选择资料和缓存的父目录。
3. 按界面启动本地服务。首次启动需要联网获取镜像和依赖，并构建应用镜像；不是完全离线安装。
4. 使用发行包所配置的认证服务注册或登录。若没有可用的真实发行安装包，请使用[完整容器启动方式](../docs/getting-started.md)。

使用安装包无需另行安装 Git、Python 或 Node.js。大型本地模型权重不包含在安装包内；需要语音或本地模型时，按[模型部署帮助](../docs/deployment/local-first.md)准备。

## 停止、资料位置和备份

通过界面停止本地服务会保留数据。数据库保存在 Docker 管理的数据卷中；文件和缓存位于首次选择的目录，默认位于应用的用户数据目录。

请同时保留资料、数据库和原始受保护设置。受保护设置与 Windows 用户有关，直接复制到另一台机器或另一个 Windows 用户下不是受支持的迁移方式。已创建工作区不能通过重新选择目录直接搬家。

现有工作区的运行包版本不一致时，应用会拒绝自动替换。升级前应先备份，不要删除配置来绕过版本提示。

## 常见问题

- **Docker 未就绪**：打开 Docker Desktop，等待引擎启动，检查 Linux 容器模式。
- **端口冲突**：停止占用该端口的应用后重试。
- **首次启动失败**：检查网络、可用磁盘和 Docker 状态；保留工作区与设置后再重试。
- **账号登录失败**：确认安装包使用真实可用的认证项目；验收用合成配置不能登录。
- **配置或密钥无法读取**：保留原文件，不要删除后重新生成；从同一 Windows 用户下的可靠备份恢复。
