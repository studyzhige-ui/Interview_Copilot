## 1. 这份旅程描述什么

我们要还原的是：一个人从产生求职需要，到判断方向、获得机会、参与招聘、作出选择、完成入职或结束本轮求职，在现实中要完成哪些工作，以及哪些工作反复发生。

招聘方的“网申—面试—录用”只覆盖其中一部分。候选人还需要维护资料与求职意向、整理经历、比较多个机会、处理没有回应和不确定结果，并决定继续或结束本轮求职。学校事务及其与求职的时间权衡不属于本轮产品职责。

本稿保留四个字段，但明确其含义：

| 字段 | 记录标准 |
|---|---|
| 阶段 | 按候选人当前要解决的问题划分，有触发条件；不是强制步骤或固定页面 |
| 用户要完成的工作 | 即使不用我们的软件也存在的真实任务与决定；不写“点击某按钮” |
| 产品应保存的结果与规则 | 候选人应能找回和继续使用的成果，以及区分正确与错误状态的业务规则；本列是设计推论 |
| Agent 可以承担的工作 | 具体可委托的整理、研究、辅导和执行工作；说明所需依据及何时交回用户，本列是能力候选 |

产品列与Agent列并不表示已经选定全部功能。产品边界、外部执行权限、实时面试辅助范围，需要在理解旅程后形成新的决定。旧文档既不自动授权，也不自动排除。

本轮完成了已有14家竞品的公开页面核验，并补充招聘管理工具与招聘渠道对照。公开页面证明的是“该产品这样描述能力”，不是功能实测。真实流程依据主要来自字节、华为、美团、腾讯音乐、高校服务和两篇候选人公开自述；尚未进行用户访谈，样本偏向科技企业，不能宣称覆盖全部行业。

## 2. 求职不是所有人共用的一条流水线

三个层次同时存在：

- **个人层面**：方向、约束、可投入时间、职业资料和持续学习，跨多个岗位与求职周期。
- **机会层面**：每家公司、岗位或团队的接触、申请、考核和决定，可以并行，也可能受企业规则限制而互相等待。
- **工作层面**：一份简历、一场笔试、一项跟进、一次训练，有自己的开始、结果和后续用途。

下列路径用于理解关系，实际顺序由招聘项目和邀请决定：

```text
求职需要 → 方向与条件 ↔ 能力和材料准备
                      ↓
持续发现机会 → 评估与选择 → 联系/内推/网申
                                  ↓
                         筛选与初步沟通
                                  ↓
                   [笔试 / 测评 / 作业 / 在线初评]
                                  ↕
                       面试准备 ↔ 多轮面试
                                  ↓
                      结果等待 / 反馈 / 调剂
                                  ↓
                  意向与条件沟通 → 正式Offer与选择
                                  ↓
                  [核验 / 签约 / 入职条件办理]
                                  ↓
                        报到 / 实习与转正分支

任一阶段：补资料、改期、继续找其他岗位、退出或暂停
每次考核之后：记录 → 复盘 → 改进 → 影响下一次准备
```

方括号表示条件性环节。背调可能在Offer前后，测评可能在面试前后，HR沟通可能在多处发生。求职成功也不是唯一结束方式：暂停、继续升学、暂不换工作、拒绝所有现有机会都应能被表达。

## 3. 完整旅程工作图

### A. 个人资料与求职意向、个人练习场（已确认）

A阶段产品定义已于2026-09-13完成，完整定义见[A阶段定稿](discussions/A-personal-profile-and-preparation.md)。原J01—J03合并为A1，原J04对应A2；旧编号仅用于识别研究稿中的引用。

| 阶段 | 用户要完成的工作 | 产品应保存的结果与规则 | Agent 可以承担的工作 |
|---|---|---|---|
| **A1 个人资料与求职意向（原J01—J03）** | 以BOSS资料页面为基础，自主填写、导入和维护信息、意向及经历；按需润色 | 保存个人资料与附件；UI和Agent能力同源；允许空缺；档案冲突修正由用户决定 | 调用导入、读取和编辑能力；个性化润色；按需检查；本次交互读取档案后发现冲突时轻量提醒 |
| **A2 个人练习场（原J04）** | 选择专业知识、技能、经历或自定主题，进行可随时切换的学习与问答练习 | 保存练习记录、用户保留的笔记及继续练习的问题；准备成果与档案分别保存；维护常用职业精选内容库，结合个人资料并按需生成练习 | 组织内容、讲解、提问、追问和反馈，支持下次继续；涉及档案事实冲突时提示用户决定 |

面向各职业领域。个人练习场提供统一入口、单次练习页与考核复盘页，承接自由练习和岗位准备；与岗位工作台的入口访问同一份练习或复盘记录。有岗位即可准备，不要求先收到考核邀请。用户不必填完资料或完成学习计划才能开始使用。学校事务和个人时间权衡不属于A阶段职责。

### B. 招聘机会与投递（已确认）

B阶段产品定义已于2026-09-13完成，完整定义见[B阶段定稿](discussions/B-opportunities-and-applications.md)。采用“公司招聘目录＋官方岗位列表”，当前不建设全量公共岗位库。

| 阶段 | 用户要完成的工作 | 产品应保存的结果与规则 | Agent 可以承担的工作 |
|---|---|---|---|
| **J05 发现招聘机会** | 浏览公司招聘目录，进入企业官方岗位列表 | 保存公司概况、批次、人群、地点与岗位方向摘要、官方入口及核验时间；后端每日更新目录；摘要不代表全部岗位范围 | 按用户需要查询目录、访问官方岗位列表 |
| **J06 分析与选择机会** | 获取公司推荐或具体岗位匹配，选择要准备投递的岗位 | 保存分析依据和结果；公司概况不能替代具体JD；按用户需要提供列表或Excel | 读取个人资料，推荐公司或到官网搜索岗位、读取JD并分析优先级，说明实际检索范围 |
| **J08 岗位工作台中的简历准备** | 选定岗位，修改、检查、预览和导出岗位简历 | 从准备投递时创建岗位卡片和持续使用的工作台；保存JD及岗位材料；ATS工具与个人资料页复用 | 基于个人资料和当前岗位JD辅助优化简历，调用编辑、检查与导出能力 |
| **J09 网申填写与检查** | 在内置浏览器的招聘页面填写、检查并完成投递 | 与该岗位工作台共享资料；利用网站已有解析结果；记录实际使用材料与提交结果 | 结合个人资料、当前岗位JD和优化简历辅助填表，检查合理性、格式及遗漏，交给用户检查 |

J07取消。内推码及渠道仅作为实际网申字段处理。岗位A的工作台与浏览器只按需加载个人资料和A岗位资料；切换岗位B后不沿用A岗位的JD、简历及专属上下文。

### C. 招聘进程、面试准备与复盘（本轮设计已确认）

完整关系见[C阶段文档](discussions/C-selection-and-interview.md)。招聘进程统一管理；个人练习场集中承接自由练习、岗位准备与复盘，岗位工作台提供直接入口，打开相同界面与同一份记录。

每个岗位只动态展示已经获知的阶段及状态，不预设固定轮次或未来阶段占位。例如A展示“投递 → 笔试 → 一面”，B展示“投递 → 一面 → 二面 → HR面”。后续通知到来再更新对应岗位。自由练习随时可用；岗位工作台创建后即可持续进行岗位准备，与阶段展示分开。

| 工作 | 用户要完成的工作 | 产品应保存的结果与规则 | Agent 可以承担的工作 |
|---|---|---|---|
| **进程管理（原J10、J11、J12、J14、J16）** | 处理考核邀请和确认链接，参加实际考核，手动补记已面试或推迟等变化 | 保存有依据的事件，更新岗位卡片、时间线及相关日程；仅时间过去不推进；下一轮明确承接本轮时可据此更新通过 | 自动跟踪邮件并读取页面结果，关联岗位及轮次、处理确认事项、调用进程更新能力；不自动跟踪短信和电话 |
| **面试准备（J13）** | 从个人练习场或岗位工作台开始、继续专项复习、问答或模拟面试 | 同一内容库支持自由练习和岗位准备；专项记录归属当前岗位，两入口共享同一成果 | 使用相关个人资料、共享知识及当前岗位JD、简历与轮次要求组织准备；不带入其他岗位资料 |
| **复盘（J15）** | 补充具体考核场次的记录与材料，分析表现并继续练习 | 复盘关联岗位及场次；两个入口打开同一份复盘；改进内容可继续发起该岗位练习 | 整理问题、回答与反馈，辅助复盘并衔接练习；档案事实冲突由用户决定是否修正 |

“练习内容”表示练什么，“练习上下文”表示是否为某岗位准备。岗位准备可以直接复习基础知识，不必转入自由练习。共享的是知识和能力，隔离的是岗位JD、简历与过程记录。

| 工作 | 用户要完成的工作 | 产品应保存的结果与规则 | Agent 可以承担的工作 |
|---|---|---|---|
| **J17 维护Offer** | 维护意向、正式Offer及与HR确认的条件 | Offer关联原岗位，保存录用情况、工作内容、地点安排、薪酬、福利、发展及个人考虑；未知不补猜 | 整理用户提供的信息，补充有来源的官方背景，不用公开待遇代填个人条件 |

| **材料交接（合并J19、J20）** | 按具体通知准备、提交及核对材料，办理交接 | 每个Offer有清单：事项、接收方、入口、期限、办理情况和依据；关联原岗位 | 从实际通知整理清单，辅助准备与核对；已提交不等于对方已确认完成 |
| **J21 转正场景复用** | 收到转正考核时准备，收到转正Offer后维护和比较 | 复用C阶段考核和D阶段Offer功能，不建设独立实习管理系统 | 沿用既有进程、准备、复盘和Offer能力 |
| **J22 结束本轮求职** | 主动使用全局结束开关 | 停止本轮主动跟踪和提醒，保留资料与历史，不自动改写其他岗位结果；有确定Offer时恭喜，无确定Offer时通用祝福 | 响应结束操作，停止主动求职任务，不推断用户去向 |

## 4. 校招、实习与早期社招如何分叉

这三类描述的是招聘处境，不是三个互斥的人群标签；同一个人可能在实习期间准备校招，或毕业后比较社招和允许参与的校招项目。

| 维度 | 校招 | 实习 | 早期社招 |
|---|---|---|---|
| 进入条件 | 核对届别、毕业时间和项目资格，不能仅用年龄判断 | 核对在读要求、每周出勤、持续时间和到岗时间；区分日常与转正项目 | 核对岗位经验要求、现有工作与可到岗条件；“早期”不代表所有岗位要求相同 |
| 时间组织 | 招聘批次、提前批/秋招/春招/补录需逐个核验，不能靠固定月份模板断言 | 岗位和项目可能有不同起止时间；课程、论文与实习安排会冲突 | 岗位开放、当前工作和面试安排共同决定节奏；不套校招日历 |
| 申请限制 | 可能有志愿、次数、先后处理与不可更换规则 | 内推、重复申请、转正资格按项目确定 | 可多岗位投递也不代表能同时面试；美团R5即提供反例 |
| 考核形式 | 可能有统一考试、岗位笔试、AI初评、群面和多轮面试 | 可能有直接团队面试或项目规定的测评，实际邀请为准 | 经历与项目讨论可能较重，是否有笔试/作业由岗位确定 |
| 收尾 | 公司Offer之外可能还有学校就业协议与毕业报到事项 | 实习录用后还有实习结束、评估、续期或转正分支 | 录用核验、原工作交接与到岗协调需要单独管理 |

AI、研发等专业差异主要改变准备内容和考核方式；没有证据前，不把某一种技术题型推广为全体用户必经步骤。国企、银行和中小企业仍需扩充样本。

## 5. 贯穿全程的工作与异常路径

### 5.1 每个阶段都可能发生的四类工作

| 工作 | 必须在旅程中体现的内容 |
|---|---|
| 时间与精力分配 | 统筹课程、在职工作、投递、学习和多场考核；显示时间冲突及准备成本，允许用户减少任务和暂停 |
| 沟通与等待 | 记录谁答应做什么、何时回复、下次找谁；支持用户手记电话和线下沟通，不要求完整接入所有聊天平台 |
| 信息核实与资料更新 | 看清来源、时间和适用范围；发现旧规则、JD变化、简历更新或不一致通知时修正理解 |
| 经验与策略调整 | 每次经历可影响训练、材料、机会优先级和方向；改变有理由，旧结论可失效，不给用户永久贴标签 |

### 5.2 必须能够表达的实际情况

| 情况 | 正确记录方式 | 后续工作 |
|---|---|---|
| 收藏页失效或岗位关闭 | 保留看到时的JD及“已关闭”证据，不能因为链接打不开就认定关闭 | 寻找官方入口或联系确认，决定是否继续 |
| 聊天后直接收到面试，无网申编号 | 从接触/邀请开始记录，允许前序未知 | 补必要上下文，不强迫虚构投递 |
| 同一岗位来自内推、官网和平台 | 保留渠道和外部编号；判定同一机会需证据 | 确认是否已提交以及渠道规则，避免重复申请 |
| 公司只允许一个岗位在面试中 | 记录公司层面的限制及其他申请等待关系 | 选择优先岗位，核实原流程终止再推进另一个 |
| 简历已改，但不确定面试官看到哪版 | 保留申请时版本、更新记录和可见性未知 | 根据招聘方规则核实，准备必要补发材料 |
| 状态长时间不变 | 保存最后确认事件与核验时间；不自动改为拒绝 | 依据实际承诺与渠道适时跟进，也可停止个人跟踪 |
| 改期只发出了请求 | 原安排仍有效，新时间是请求/待确认 | 跟进回复，确认后更新生效日程 |
| 缺席、掉线、测评链接过期 | 实际考核状态与原因；补考/重约是另一个事件 | 联系指定人员核实是否可重约，不假定有补考资格 |
| 面试岗位与投递岗位不同 | 保留原岗位和变更来源，不覆盖旧申请历史 | 重新评估是否接受，准备新的岗位上下文 |
| 已过面试但等审批/名额 | 记录通知原文、已知结论及未知项 | 跟进且继续管理其他机会，不标“已有正式Offer” |
| 有Offer但希望等待另一家 | 正式Offer及截止，与另一家的阶段分列 | 分析风险、申请延期并核验批准，不自动延期 |
| 转正未成、名额取消或入职推迟 | 记录实际通知；不从结果反推个人能力不足 | 更新计划、材料和可到岗条件，恢复其他机会 |
| 只有本人回忆，没有录音 | 标注回忆来源、时间及不确定片段 | 允许局部复盘，不能补造逐字稿 |
| 决定休息或不再换工作 | 暂停/结束个人求职周期，保留外部事实 | 处理未完承诺、停止提醒并留下重新开始入口 |

其中候补、名额变化、时间冲突等部分来自个案或合理场景推演，发生频率尚未验证。它们是需要覆盖的可能性，不是对每家公司的事实断言。

## 6. 用三段代表性故事检查是否遗漏工作

以下为依据研究构造的场景，不是声称访谈过的真实人物。

### 场景一：实习转正尚未确定，同时准备秋招

一名在读学生希望留在目前实习团队，但HR尚未确认转正名额；外部秋招已开放。

他需要保存现有实习成果，确认转正评估安排，同时检查外部校招资格、选择有限投递机会并准备不同材料。学校课程与面试冲突时需要改期；收到外部Offer后，需要比较确定条件与尚未确定的转正可能。

产品应能同时表示“已经在实习”“转正尚未确认”“外部申请进行中”。Agent可整理成果、查询项目规则、协助准备和比较；不能把有转正机会记成已有保底Offer。

检查：J01、J03、J06—J09、J12、J17—J18、J21是否能连起来？实习结束后，经历是否仍能用于外部申请？

### 场景二：同公司两个社招岗位，一个正在面试

一名工作不久的候选人通过推荐申请A岗位，又发现B岗位更符合期望。招聘方规定同一时间只能进行一个岗位面试。他更新了简历，但不确定招聘方看到哪版；同时必须兼顾当前工作。

用户需要先理解流程限制和改变方向的代价，联系确认后再决定是否退出A；B进入流程后要重新组织准备。结束面试后，还需要跟进结果、办理录用核验和协调到岗。

产品需保留A/B关系、退出原因、各阶段使用材料以及工作日程。Agent可以说明限制、准备沟通和更新安排，不应直接同时推动两个互斥流程。

检查：J08—J09、J12—J13、J16、J19—J20是否共享必要信息，且不把技术执行成功当成流程获准？

### 场景三：校招笔试已交，面试改期未确认，另一家公司Offer快到期

用户完成了一场笔试，但结果不公开；另一场面试因课程冲突申请改期，尚未收到同意；第三家公司给出的正式Offer即将到回复期限。

用户现在需要的不是一个“都在进行中”的看板，而是清楚知道：笔试在等评估、旧面试时间仍有效、Offer仍按原截止时间处理。是否继续等和如何取舍由用户决定。

Agent可将三件事分开梳理、准备沟通、给出情境比较。不能把交卷写成通过、把改期请求写成新日程、把申请延期写成已获延期。

检查：J11、J12、J16、J18是否各自有正确的结果和依据，又能放在同一个时间安排中比较？

## 7. 早期产品理解推论（历史研究，已由阶段定稿承接）

这轮更有依据的产品中心是：**帮助候选人在多个机会、不完整信息与有限时间之间，持续完成有结果的工作和有依据的选择。**

由此可以提出六项候选责任，而不是立即划六个页面：

1. 理解求职条件和目标，并随实际情况更新。
2. 保存可复用的经历与材料，让“写了什么、交了什么、后来改了什么”可追溯。
3. 理解机会与招聘过程，包括等待、调剂、退出和企业特定限制。
4. 把准备与训练落实到具体考核，并让复盘产生下一步改变。
5. 支持条件比较、决定以及签约到入职的办理工作。
6. 在全程提供沟通、时间管理、信息核验与可接手的Agent协作。

AI native的价值应在这些工作中检验：用户可以从自己的目标出发委托任务，成果进入可查看、可编辑的产品工作区；直接操作与Agent协作能够互相接续。

这并不要求先确定Agent数量、Memory架构、数据库、四个一级入口或旧MVP范围。本轮不冻结上述任何事项。
