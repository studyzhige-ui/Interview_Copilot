# Interview Copilot 产品信息架构

> 状态：待产品审阅  
> 日期：2026-09-03  
> 上位文档：[01-product-definition.md](./01-product-definition.md)、[02-mvp-definition.md](./02-mvp-definition.md)、[03-core-user-journey.md](./03-core-user-journey.md)  
> 本文定义产品区域及其职责，不冻结路由、组件、视觉布局或数据库结构。

## 1. 总体结构

产品设置四个一级入口：

```text
今天　　求职　　面试　　资料
```

另有两个辅助入口：

```text
活动中心　　设置
```

Copilot 横跨整个产品，是自然语言交互和 Agent 执行层，不是与四个业务入口并列的普通页面。

## 2. 一级入口

### 2.1 今天

“今天”帮助用户判断现在发生了什么、需要处理什么。它只展示其他业务区域中已经存在的信息，不单独维护一套数据。

主要内容：

- **已确认提醒**：已成为正式事实且与时间相关的事项；
- **待确认事项**：Agent 根据邮件等来源提出、等待用户确认的流程变化。

待确认事项被用户接受后，先更新对应机会；由更新产生的正式时间事项再进入已确认提醒。未确认内容不得提前显示成事实。

每条信息都能跳转到所属机会、面试或来源，也能作为结构化引用加入 Copilot，让用户直接提出下一步要求。

“今天”不承担岗位看板、泛化建议流、面试历史或 Agent 完整运行日志。

### 2.2 求职

“求职”负责创建和管理具体机会，以及记录每个机会的真实流程。

主要内容：

- 创建机会；
- 查看全部机会及跟踪状态；
- 更新机会事实和当前阶段；
- 查看流程时间线与来源；
- 管理与机会相关的行动、面试和资料入口。

机会是一个具体公司的具体岗位。搜索和筛选岗位是 Agent 可按需调用的能力，不作为必须存在的一级入口；搜索结果只有被用户选择或明确创建后才成为机会。

机会列表适合采用横向卡片表达关键信息，机会详情承载完整流程。具体卡片字段和更新交互由后续规格确定。

### 2.3 面试

“面试”负责围绕真实机会进行准备、练习和复盘，也允许用户进行不绑定具体机会的通用专项练习。

包含三个相互连接的工作区：

- **专项练习**：基础知识、项目细节和薄弱点训练；
- **模拟面试**：接近真实提问、追问和节奏的面试过程；
- **面试复盘**：录音、转录、说话人、问答、分析、报告和历史记录。

从机会或首页提醒进入时，面试区域应继承对应岗位、面试阶段和必要资料，不要求用户重新选择上下文。复盘结果可以影响后续准备，但不能直接改写个人档案。

### 2.4 资料

“资料”保存用户级、可跨机会复用的职业信息和来源资产。MVP 首先包含个人档案与简历附件。

个人档案采用三个职责区：

- 章节导航；
- 档案查看与维护；
- 附件、完整度和辅助信息。

档案章节包括个人信息、个人优势、期望职位、工作经历、项目经历、教育经历、资格证书、社团或组织经历、志愿者经历和专业技能。

个人档案、简历附件和 Agent Memory 相互独立：档案是用户维护的正式事实，简历是面向具体用途的文件，Memory 是可以修订和失效的 Agent 理解。

项目经历可以关联代码仓库、演示、论文和技术文档等来源。未来新增其他资料类型时，应继续放在“资料”之下，而不是增加新的一级导航。

## 3. 辅助入口

### 3.1 活动中心

活动中心展示 Agent 和自动化工作的完整记录，包括正在执行、等待确认、已完成、失败和已停止的任务，以及对应来源和结果。

“今天”只投影当前需要用户关注的事项；活动中心保存更完整的运行历史。二者不能各自维护一套任务状态。

### 3.2 设置

设置负责账户、隐私、Agent 权限、通知、外部连接和模型等产品配置。它不承载求职业务内容。

长期记忆的查看、修正、失效和删除入口可以位于设置中的个性化管理，但具体归属将在 Memory 设计时确认。

## 4. Copilot 的跨产品角色

Copilot 在所有区域保持可用，并能接收三类上下文：

- 用户主动输入的目标；
- 用户通过 `@` 或快捷操作引用的产品对象；
- 当前区域与所选对象提供的工作上下文。

Copilot 可以读取相关信息、调用与 UI 相同的业务能力、展示执行进度，并把用户带到结果所在的工作区。它不能绕过确认、权限和来源规则，也不应让用户为完成任务而学习内部页面结构。

对话历史可以被保留，但“聊天记录”不是产品的业务中心；真正产生的机会、行动、复盘和档案变化必须落入各自所属区域。

## 5. 核心对象的归属

```text
用户
├── 个人档案与资料
├── 多个机会
│   ├── 流程事实与来源
│   ├── 行动与提醒
│   └── 真实面试
│       ├── 准备
│       └── 复盘
├── 通用练习与模拟面试
├── Agent 活动
└── 可管理的长期记忆
```

“今天”是上述对象的当前投影，Copilot 是操作这些对象的跨产品入口，两者都不拥有重复业务数据。

## 6. 导航与上下文原则

- 从提醒、待确认事项、机会或 Agent 结果进入工作区时，保留原对象上下文；
- 一个对象只有一个权威归属，其他区域只引用或投影；
- 重要信息提供可跳转的来源入口；
- UI 与 Agent 执行相同语义的业务操作；
- 用户可以从任何对象继续与 Copilot 协作；
- 不因功能增加而随意增加一级入口；
- 空状态、错误状态和等待确认状态由后续交互规格定义。
