# 页面结构：已确认方向

> 更新：2026-09-14。依据：用户本轮导航与页面说明，以及[功能全景](05-product-capability-map.md)。
> 本文只记录已确认的结构与视觉方向，不表示模块排布、组件、尺寸或交互细节已经定稿。旧04文档和上一轮助手提出的导航草案不作为本轮决定。

## 1. 导航与页面职责

主要工作入口在侧边导航中组织，设置相关内容集中在左下角。采用Today作为首页；日程、通知与待确认事项在首页直接呈现，不再归入一个宽泛的“全局工具入口”。

| 入口 | 已确认的内容与呈现方向 |
|---|---|
| Today首页 | 用户登录后首先看到的页面；采用四个区域围绕中央问候、简短摘要与Agent输入的构图。左上本月日历、右上待我确认、左下最近安排、右下其他动态与消息；信息充足且视觉愉悦 |
| 个人资料 | 承接个人资料与求职意向、简历及已确认的相关能力；资料内容沿用A阶段以BOSS简历页为基础的定义 |
| 岗位市场 | 原“招聘机会”入口改名。继续采用公司招聘目录＋官方岗位列表，承接收藏、机会分析等能力；兼顾清晰的信息展示、美学设计及Agent嵌入。改名不代表开始维护全量岗位库 |
| 我的投递 | 原“我的岗位”入口改名。横向岗位卡片按顺序竖向排列；已结束流程且未获得Offer的岗位在列表最末尾以灰色卡片堆叠呈现。此前确认的投递前岗位工作台仍从此入口访问，卡片按事实标明是否已投递 |
| 个人练习场 | 集中承接自由练习、岗位准备、练习内容与考核复盘；保持不同入口打开同一练习或复盘的原则 |
| Offer池 | 提供筛选、单个Offer详情与多个Offer对比；以“池子中浮动的Offer”作为视觉探索方向，同时保留清晰可操作的信息呈现 |
| 面经社区 | 当前主要职能偏向面经题库与参考内容，社区互动后续完善；先前纳入的社区能力并未取消 |
| 插件市场 | 保留未来扩展入口与能力方向；沿用已有连接和能力体系，提供外部服务、专业内容及工具的扩展体验。导航中规划位置不改变其未来功能定位 |
| 设置 | 设置与连接、个性化等设置相关内容，入口位于左下角 |

用户提供的第一张图用于参考左下角账户与设置相关内容的收纳方式，不因此新增充值、会员等功能要求。

## 2. 岗位卡片与工作台

用户在“我的投递”中点击岗位卡片，通过动画进入对应岗位工作台。工作台上方呈现该岗位的进程卡片，下方大部分空间用于该岗位的实际工作。

上方进程只展示已经获知的节点及状态。例如A是“投递 → 笔试 → 一面”，B是“投递 → 一面 → 二面 → HR面”；不预设未来轮次。下方工作空间持续承接岗位资料、申请材料、网申、准备、记录与复盘，以及已发生的录用交接工作。

进程展示与工作能力分别处理：岗位工作台创建后即可练习和准备材料；自由练习随时可用。取得意向或Offer后沿用原岗位记录进入Offer池；未获得Offer但流程尚在进行中的岗位，不属于底部已结束的灰色卡片。

材料编辑、练习、复盘和Offer详情暂沿用共用页面方案，从不同入口访问同一份业务记录，不复制建立第二套成果。

简历制作进入独立编辑页面，提供内容编辑、模板、排版、分页、版本与导出。从个人资料和岗位工作台进入同一个编辑器，分别打开基础简历或该岗位的专属简历。简历保存内容、局部格式与版式；修改简历不自动回写个人档案或覆盖已提交的材料。UI与Agent共用文档修改能力，修改可查看、可撤销。导出包含PDF、可编辑DOCX、图片和纯文本；DOCX的最终分页需考虑Word/WPS的字体与排版差异。

## 3. Agent与页面融合

Agent输入需要无缝嵌入各页面的实际工作，而不是单独列为导航工具。输入区的具体位置与展开形态随页面设计确定；嵌入页面不改变UI与Agent调用同源能力的原则。

个人资料页的Agent入口应始终可达，不放在长资料内容的末尾要求用户滚到底部。资料正文与Agent入口分开布局，正文滚动不将输入区带离当前工作区。资料按模块使用结构化字段表单；简历上传、解析与用户选择更新档案的流程沿用A阶段定义，不另设TXT资料导入入口。

各页面的资料范围继续沿用功能全景的规则：单岗位工作只使用相关个人资料与当前岗位资料；多Offer比较只读取所选对象的比较资料。Today展示多个岗位信息，不等于把所有岗位的材料和对话加载进Agent。

真实考核现场仅提供记录相关能力，不因存在统一Agent入口而开放知识回答或作答提示。首页的待确认事项也不将此前已允许自动处理的明确进程变化全部改为人工审批：清楚承接上一轮的下一轮通知，仍按C阶段规则更新。

## 4. Today的四个区域与交互

| 区域 | 已确认的职责 | 已确认的交互 |
|---|---|---|
| 左上：本月日历 | 整块用于月历，突出今天，以圆点标识有安排的日期，不在格内堆放完整事项 | 支持月份切换；点击日期联动左下角展示当天安排 |
| 右上：待我确认 | 用户需要决定、补充或检查的事项，说明原因与可执行操作 | 简单事项直接处理；复杂事项进入对应材料或页面 |
| 左下：最近安排 | 默认按时间展示近期面试、笔试、材料截止等具体事项，包括岗位、时间与确认状态 | 点击日历后切换为选中日期的安排，提供返回最近安排；点击事项查看详情或进入对应工作 |
| 右下：动态与消息 | 承接其他三区之外的信息，例如未在其他区承接的Agent任务及成果、岗位市场更新、系统与连接消息；不重复日历、安排或待确认的内容 | 按信息类型区分，点击查看对应成果、来源或工作页面；市场更新可以合并摘要，避免刷屏 |

右下角按内容是否已被其他区域承接来判断，不按“由谁发出”判断。Agent识别了面试安排，该安排仍进入日历与最近安排，不再生成右下角同义通知；Agent任务需要用户检查时，以待我确认为主要处理位置，不在右下角重复该请求。日历日期标记与左下具体安排保留已确认的联动关系。

中央保留问候、简短摘要与Agent输入框。四区不要求严格等大；具体空间比例、首屏条数与输入后展开方式在后续页面方案中确定。页面结构参考用户截图的构图，截图内的示例岗位、审批文字和数量不构成产品规则。

### Today交互原型方向

用户已同意进入页面原型设计。四区采用上排、中央输入、下排的布局，桌面初稿以上排约45%、中央约18%、下排约37%作为空间起点，条数和比例随实际内容调整。完整月历预留六周高度；其他区域优先呈现少量重要事项，可原处展开更多。小窗口允许页面重排和滚动，不压缩文字强行塞入首屏。

查看简要信息在卡片原处展开，简单决定直接处理，持续编辑或办理工作进入对应共用页面。中央输入在开始打字时适度增高；提交后展开任务对话与结果，输入移至对话底部，保留返回Today操作。返回后恢复日期选择、已有展开状态及未结束的对话。原型使用示例内容展示这些行为，不表示已连接真实业务或Agent。
