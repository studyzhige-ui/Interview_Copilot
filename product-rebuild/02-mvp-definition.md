# Interview Copilot MVP 定义

> 状态：已确认  
> 日期：2026-08-30  
> 上位文档：[01-product-definition.md](./01-product-definition.md)  
> 本文只定义第一个可用版本要验证的价值闭环，不定义页面、视觉、领域模型或技术实现。

## 1. MVP 要验证什么

MVP 要验证的不是“AI 能不能生成求职内容”，而是：

> **当岗位、流程、行动、面试准备和复盘被放进同一个持续状态中，并且用户既能直接操作，也能让 Agent 操作时，Interview Copilot 是否能成为用户反复使用的个人求职工作台。**

第一版不追求覆盖完整产品的所有能力，只建立一条从机会进入到面试经验回流的最小闭环。

## 2. 目标使用场景

目标用户正在寻找计算机或 AI 相关岗位，同时跟进多个机会。其中至少一个机会已经或即将进入面试阶段。

用户过去依靠招聘网站、邮件、表格、日历、文件和 ChatGPT 分别完成这些工作。MVP 应让用户第一次能够在一个产品中连续完成：发现或导入机会、跟踪进展、知道下一步、准备面试、完成复盘，并让复盘结果影响下一次准备。

## 3. 最小价值闭环

```text
建立基本职业信息并导入简历
→ 搜索或导入岗位
→ 选择并跟踪多个机会
→ 查看已经成立的下一步行动
→ 针对一个真实岗位准备面试
→ 完成一次模拟面试或真实面试复盘
→ 将有来源的复盘结果用于下一次准备
```

只有最后一步能够使用前面累积的状态和证据，这条闭环才算成立。单独完成岗位看板、聊天问答或题库都不构成 MVP。

## 4. MVP 必须具备的能力

### 4.1 用户与求职基础

- 保存基本职业方向、偏好、经历和一份主要简历；
- 用户能够查看和修正自己的正式信息。

### 4.2 机会发现与进入

- Agent 能从公开来源协助搜索岗位；
- 用户能通过链接、JD 文本或手动录入将岗位加入工作台；
- 系统能够保留岗位来源，并避免明显重复。

### 4.3 多岗位流程与下一步

- 用户能同时查看和更新多个岗位的真实进展；
- 每个岗位能够记录已经发生的关键事件；
- 系统能够显示已经成立的 Next Action、截止时间和需要用户确认的事实；
- 用户可以从 Next Action 直接进入对应工作。

### 4.4 面试准备与复盘

- 准备内容能够同时使用目标岗位、用户简历和既有复盘；
- 用户能进行一次与目标岗位相关的模拟面试，或导入一次真实面试的录音、转录或文字记录；
- 复盘必须区分原始来源、观察和建议，不能把模型判断直接写成用户事实；
- 下一次准备能够引用此前有来源的薄弱点或有效表现。

### 4.5 最小 Agent-native 体验

- 用户既可以通过普通 UI，也可以通过自然语言完成上述核心工作；
- 两种方式必须读取和改变同一份求职状态；
- Agent 能组合多个步骤，但正式改变必须经过产品业务规则；
- 系统可以根据真实 Next Action 和时间进行提醒，但第一版不执行高风险自主外部操作；
- 用户能够看到 Agent 正在做什么、需要什么确认以及工作是否真正完成。

## 5. MVP 明确不包含

- 自动登录并轮询所有公司招聘网站；
- 无差别批量投递或全自动申请；
- 自动向招聘方发送邮件；
- 完整 Gmail、Calendar 和招聘平台连接器体系；
- 插件市场和第三方开发者生态；
- 复杂多 Agent 团队与完全自治的长期任务；
- 实时面试代答；
- 完整 Offer 比较与职业决策；
- 面向所有职业的专业知识和能力模型；
- 商业化、组织协作和企业招聘功能。

这些能力可以属于长期产品，但不能成为第一个版本成立的前提。

## 6. MVP 成立的判断

MVP 只有在真实目标用户能够完成以下过程时才成立：

1. 不依靠外部表格，管理至少三个同时推进的真实岗位；
2. 打开产品后，能够准确判断当前最重要的已成立行动；
3. 使用同一份岗位和个人上下文完成一次面试准备；
4. 完成一次模拟面试或真实面试复盘；
5. 在下一次准备中看到前一次复盘产生的、可追溯的影响；
6. 至少一次通过自然语言完成原本需要操作多个页面的工作；
7. 用户能够纠正错误事实，并理解哪些内容是事实、观察、建议或待确认操作。

上述过程首先用一名真实用户的一次真实求职周期验证，再扩大到更多测试用户。页面数量、Agent 消息数和 Tool Call 数量不能证明 MVP 成立。
