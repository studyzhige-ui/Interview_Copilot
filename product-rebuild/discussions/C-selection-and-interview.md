# C阶段：招聘进程、面试准备与复盘

> 状态：阶段主体已确认；2026-09-14补充现场记录边界。
> 本文替代原旅程J10—J16的拆分方式，明确个人练习场、岗位工作台、面试准备及复盘之间的关系。

## 1. 功能关系

个人练习场是集中开展练习、面试准备和复盘的入口。岗位工作台围绕某一个岗位组织全程工作，提供该岗位准备与复盘的直接入口。面试准备和复盘是实际工作，不另建与这两个入口重复的系统。

| 名称 | 职责 | 与其他部分的关系 |
|---|---|---|
| 岗位卡片 | 展示某个岗位的当前进程及安排 | 可以进入该岗位工作台 |
| 岗位工作台 | 集中管理一个岗位的JD、简历、网申、考核安排与相关成果 | 提供准备与复盘入口，打开与个人练习场相同的功能界面 |
| 个人练习场 | 集中开展自由练习、岗位准备和复盘 | 可以直接选择岗位，无需先找到岗位卡片再进入工作台 |
| 面试准备 | 学习、专项复习、问答练习与模拟面试 | 使用统一练习能力；关联岗位时加载该岗位上下文，基础知识仍然可用 |
| 复盘 | 整理具体考核中的问题、回答、反馈及改进行动 | 关联具体岗位与考核场次，从两个入口打开同一份复盘 |

本文统一使用“岗位工作台”，表示某一岗位的专属工作空间；不另设一个含义重复的“个人工作台”。

## 2. 招聘进程统一管理

原J10、J11、J12、J14、J16在产品中共用一套进程管理能力，表达筛选、笔试/测评、多轮面试、等待和结果等不同事件，不分别建设重复模块。

### 按各岗位已知进程动态展示

每个岗位的后续阶段、轮次数量与结果事先未知。产品依据实际通知、页面结果或用户补记，逐步形成该岗位自己的进程；岗位卡片、工作台和时间线只渲染该岗位已经获知的阶段及其已知状态，不预先铺出统一的完整招聘流程，也不以灰色占位展示尚未获知的二面、HR面或Offer等阶段。

| 已获知的实际进程 | 该岗位展示的阶段 |
|---|---|
| 岗位A：投递、笔试、一面 | 投递 → 笔试 → 一面 |
| 岗位B：投递、一面、二面、HR面 | 投递 → 一面 → 二面 → HR面；不补造笔试节点 |
| A岗位后来收到二面通知 | 在A已有进程上新增二面，并按通知更新相关状态；不改变B的进程 |

“已知某阶段”与“已完成该阶段”分开。例如收到一面邀请后即可展示一面及其待确认或已安排状态，无需等面试结束；完成、通过、推迟等状态仍按下表的事实依据更新。没有结果时不猜测结果，没有后续通知时不生成后续阶段。

动态变化的是该岗位的招聘进程展示。练习能力的可用性不随阶段解锁：自由练习随时可用；岗位工作台创建后，岗位准备始终可从工作台或个人练习场进入。

### 通知与更新

当前自动跟踪渠道为邮箱，不接入短信和电话的自动跟踪。用户可手动补记其他渠道或现实中发生的变化。

Agent读取招聘邮件和页面结果，识别具体岗位、考核轮次、时间和需要处理的事项。邮件要求通过链接确认时，进入链接办理，不默认每封邮件都需要撰写回复。

| 依据 | 进程处理 |
|---|---|
| 收到考核邀请 | 保存邀请及待确认事项；有明确时间的安排进入日程，标明确认状态 |
| 页面确认完成 | 保存实际确认结果，更新相应安排 |
| 用户手动更新 | 用户可标记已面试、已推迟等现实变化，产品更新该岗位进程 |
| 收到下一轮考核通知 | 同一岗位进程中明确承接本轮的下一轮通知，可作为本轮通过的依据，Agent自动更新进程，无须另等一封通过邮件 |
| 收到结果通知 | 更新岗位结果与时间线；没有时间安排的结果不创建日程 |
| 仅日程时间过去 | 不据此认定考核完成、通过或失败 |

下一轮、补考、并行测评按通知实际含义区分。确认请求不等于确认成功，改期请求不等于新时间生效；重复通知不重复创建同一事件。记录更新来源，使用户能理解进程为什么发生变化。

岗位卡片、时间线和日程呈现同一套已保存的进程信息。Agent负责识别事件并调用更新能力，产品负责同步展示；用户手动更新同样生效。

收到录用意向或正式Offer后，该岗位进入[D阶段的Offer池](D-offers-and-closing.md)。用户通过全局开关结束本轮求职后，停止主动跟踪、推进任务和提醒，保留已有进程记录。

## 3. 练习内容与练习上下文

“基础知识”和“岗位专项”不构成两套互斥内容库。一次岗位准备可以复习基础知识，也可以深挖项目或开展模拟面试。

| 维度 | 含义 | 示例 |
|---|---|---|
| 练习内容 | 这次练什么 | Python、数据库、项目讲述、销售异议处理、客户需求分析 |
| 练习上下文 | 这次是否为具体岗位准备 | 自由练习，或某家公司某岗位的某轮面试 |

### 同样内容在不同上下文中的使用

| 情况 | 使用方式 |
|---|---|
| 自由练习数据库 | 使用职业内容库与相关个人资料，围绕用户选择的知识主题学习、练习 |
| 为A公司Agent岗位复习数据库 | 使用同一套数据库知识，同时结合A岗位JD、岗位简历、项目经历及本轮要求调整题目、侧重点和追问 |
| 为B公司岗位复习数据库 | 继续使用共享知识，但仅加载B岗位上下文，不带入A岗位的练习对话或专属资料 |

用户可以在岗位准备中直接复习基础知识，不必退出岗位准备再进入另一个通用知识模块。学习、讲解、专项问答和模拟面试使用同一练习空间，准备成果按当前上下文保存。

## 4. 多个入口，同一界面与记录

### 入口安排

| 从哪里进入 | 用户操作 | 打开什么 |
|---|---|---|
| 个人练习场的自由练习 | 选择主题、知识或个人经历，不关联岗位 | 统一练习界面，以自由练习上下文开始 |
| 个人练习场的岗位准备 | 从岗位列表选择岗位；已有考核轮次时可进一步选择轮次 | 统一练习界面，带入所选岗位上下文，可开始或继续准备；没有邀请或轮次也可使用 |
| 岗位工作台的准备入口 | 直接开始或继续当前岗位准备 | 与个人练习场中该岗位对应的同一练习界面与记录 |
| 个人练习场的复盘入口 | 选择具体岗位的考核场次 | 对应场次的复盘界面与记录 |
| 岗位工作台的复盘入口 | 打开该岗位的一场考核 | 与个人练习场中该场次对应的同一复盘 |

个人练习场的岗位列表展示当前进程、考核时间和最近练习，便于集中找到需要准备的岗位；复盘入口集中展示考核场次及已有复盘。列表可以展示多岗位摘要，但打开某岗位后，Agent只使用该岗位的上下文。

不同入口打开同一条练习或复盘时，继续使用同一份记录、笔记和成果，不复制创建第二份。用户主动开始新练习时创建新的练习记录。

练习界面显示当前关联的公司、岗位及已知轮次；未关联岗位时明确显示自由练习。复盘界面显示所关联的岗位与具体场次。

## 5. 内容共享、记录归属与上下文隔离

| 信息 | 归属与加载规则 |
|---|---|
| 职业知识、通用题目、参考解析 | 共享内容，可用于自由练习与任何相关岗位准备 |
| 个人资料 | 共享基础，按当前任务需要读取 |
| 自由练习记录与笔记 | 属于个人练习场的自由练习，不因涉及某知识点而自动归入某岗位 |
| 岗位JD、优化简历、本轮要求 | 属于具体岗位，只在该岗位工作中按需加载 |
| 岗位专项练习、笔记和反馈 | 属于当前岗位的准备记录，可由个人练习场与该岗位工作台共同访问 |
| 考核记录与复盘 | 属于具体岗位及考核场次，两处入口访问同一份记录 |

共享知识不等于共享岗位过程。A岗位练过Python，B岗位仍可使用Python知识，但不会因此自动加载A岗位的问答、简历或复盘。切换岗位时，不沿用上个岗位的专属上下文。

练习表现和复盘结论不直接改写个人档案。若本次读取档案后发现事实冲突，沿用A阶段的轻量提醒，由用户决定是否修正。

## 6. 复盘回到准备

### 现场记录与事后复盘的边界

真实笔试或面试期间，产品提供与记录相关的能力，保存实际发生的内容并衔接事后复盘。现场不提供AI知识回答、答题建议、解题提示或其他作弊能力；不将原竞品中的实时答案、截图解题或资料检索作答方式纳入本产品现场功能。

记录与转写关联当前岗位及实际场次；记录内容不完整时保留缺失，不由AI补造用户回答。事后复盘可以分析与讲解，并发起后续练习。自由练习和模拟面试仍可正常提供教学、提示与反馈，它们不属于真实招聘考核的现场作答。

具体记录媒介、界面和操作方式尚未设计；记录会话结束也不自动代表招聘考核完成或通过，仍沿用第2节的事实更新规则。

用户在一次笔试或面试后补充记录、回忆或材料，AI协助整理问题、回答、反馈和需要改进的内容。复盘关联实际场次，不能把用户的回忆补写成未经证实的逐字记录。

模拟面试的问答与反馈属于练习记录，不记作实际参加考核，也不据此推进招聘状态；本节的考核复盘针对现实中已参加的场次。

复盘中需要加强的内容可以直接发起该岗位的后续练习。若涉及基础知识，使用同一份职业内容库；新练习继续归属该岗位，不要求先转入自由练习。

例如：A岗位一面复盘发现数据库问题回答不清，用户从该复盘开始数据库专项练习。无论之后从个人练习场还是A岗位工作台进入，都能继续这一练习；进入B岗位时不会自动携带它。

## 7. 一次完整使用过程

1. 收到A岗位面试邀请，Agent识别并关联岗位，保存待确认安排；链接确认成功后更新进程与日程。
2. 用户在个人练习场直接选择A岗位，或者从A岗位工作台进入准备，两条路径到达同一准备空间。
3. 用户复习基础知识、练习项目讲述或模拟面试，系统使用共享知识与A岗位上下文，保存A岗位练习成果。
4. 实际面试结束，用户手动标记已面试。若随后收到明确的下一轮邀请，Agent据此更新本轮通过及下一轮安排。
5. 用户从任一入口复盘本场面试，并围绕薄弱内容继续练习，记录始终关联A岗位及相应场次。
