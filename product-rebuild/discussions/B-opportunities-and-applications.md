# B阶段：招聘机会与投递

> 状态：产品定义已确认，B阶段讨论完成。更新：2026-09-13。
> 本文替代原旅程J05—J09及此前B阶段讨论稿。完成的是产品定义，不表示采集、浏览器或投递功能已经实现。

## 1. 阶段范围与工作

采用“公司招聘目录＋官方岗位列表”。用户可以自行浏览，也可以让Agent推荐公司或查找具体岗位；选定岗位并开始准备投递时，进入该岗位的工作台与进程。

| 阶段 | 用户要完成的工作 | 产品应保存的结果与规则 | Agent可以承担的工作 |
|---|---|---|---|
| J05 发现招聘机会 | 浏览、筛选公司招聘目录，进入企业官方岗位列表 | 保存公司概况、招聘批次摘要与官方入口；后端每日更新目录，不全量维护企业岗位列表 | 按用户意图查询目录、访问官方岗位列表 |
| J06 分析与选择机会 | 获取公司推荐或具体岗位匹配结果，选择准备投递的岗位 | 保存分析结果及来源；公司概况与岗位条件分开；输出形式服从用户需要 | 结合个人资料推荐公司，或到官网检索并读取JD，给出岗位优先级、理由及列表或Excel |
| J08 岗位工作台中的简历准备 | 针对选定岗位修改、检查、预览和导出简历 | 创建岗位卡片与工作台，保存该岗位JD及个性化材料；工作台持续承接该岗位后续工作 | 结合个人资料与JD优化简历，调用检查、编辑和导出能力 |
| J09 网申填写与检查 | 在内置浏览器中填写招聘网站表单，检查并完成投递 | 工作台与浏览器共享当前岗位资料；保存实际使用的材料及提交结果，未提交不能记作已投递 | 利用网站解析结果，补填、检查合理性与格式、发现遗漏，将填写结果交给用户检查 |

J07取消，不设置渠道规划阶段。内推码由用户自行取得，渠道及内推字段只在实际网申页面出现时处理。

## 2. 公司招聘目录

### 两级浏览

一级是我们维护的公司招聘目录，让用户了解公司做什么、正在开展哪类招聘；二级是企业自己的官方岗位列表，由企业提供职位搜索、地点和岗位分类等筛选。产品通过官方链接进入该列表，不复制维护另一份全量岗位列表。

公司信息共用，招聘项目或批次分别记录。同一公司可以有多个招聘批次；某批次的地点和岗位方向不代表该公司的全部招聘范围。

### 目录内容

| 内容 | 保存与展示方式 |
|---|---|
| 公司信息 | 名称、业务简介和领域标签，说明公司主要业务 |
| 招聘信息 | 招聘类型、批次、面向届别或人群 |
| 大致岗位方向 | 摘要展示软件、硬件、财务、销售等已知招聘方向 |
| 地点摘要 | 展示已收录地点；它不是官网所有岗位地点的完整清单，不能因摘要未列某城市就判断该公司没有对应机会 |
| 官方入口 | 招聘公告、招聘主页和岗位列表链接 |
| 信息依据 | 来源、最近核验时间 |

公司领域与招聘职业分别表达。制造业公司也可能招聘软件、金融、设计等人员；领域标签用于了解公司，不作为职业匹配的硬性限制。

### 维护方式

后端每天定时采集、去重和更新目录，处理新公司、新批次、公告变化及失效入口。面向用户的Agent使用目录完成任务，不承担公共目录的日常维护。

当前不建设全量公共岗位库。未来具备维护能力后可扩展为全量岗位库，这不构成本阶段的交付任务或使用前置条件。

## 3. Agent机会分析

| 用户需求 | 执行方式 | 结果 |
|---|---|---|
| 推荐公司 | 读取个人资料与求职意向，对照公司业务、招聘项目及岗位方向摘要 | 公司列表、优先级和推荐理由 |
| 推荐具体岗位 | 使用目录定位官方入口，在企业岗位列表中搜索、筛选并读取相关JD，再结合个人资料分析 | 具体岗位列表、匹配点、缺口、推荐理由和优先级 |
| 导出结果 | 根据用户要求组织已取得的分析结果 | 页面列表或Excel表格 |

用户可以直接要求岗位列表，无需先完成一次公司推荐。没有读取具体JD时，只能给出公司层面的判断，不能用公司简介推断岗位的地点、资格或职责。

分析结果保留所依据的来源与读取时间，说明实际检索范围及未能读取的入口。优先级针对本次实际取得的信息，不宣称是全市场排名。

参与分析的JD保留本次使用的内容及来源；用户开始办理具体岗位时，将JD保存到该岗位工作台，供简历优化、网申及后续准备共用。保存任务所用JD不等于维护全量公共岗位库；继续办理时若官网内容发生变化，应对照更新。

## 4. 岗位工作台

用户选定具体岗位并开始准备投递材料时，即可创建岗位卡片及工作台，无须等到申请提交后。

工作台是该岗位进程中持续存在的工作空间。J08是其中投递前的简历准备工作，不是工作台的全部用途。

工作台创建后即可开展当前岗位的准备，不要求已经投递或收到考核邀请；已知考核轮次时再带入该轮要求。实际参加考核后，可针对对应场次复盘。准备与复盘入口打开与个人练习场相同的界面、记录及成果，不另建练习或复盘系统。用户也可从个人练习场直接选择该岗位，无需经过岗位卡片。具体关系见[C阶段第1—5节](C-selection-and-interview.md)。

| 工作 | 产品行为 |
|---|---|
| 查看岗位依据 | 保存并查看具体JD与官方链接 |
| 个性化修改简历 | 根据JD和用户个人资料，调整该岗位简历中的经历选择和表达 |
| 检查与优化 | 使用简历检查、ATS评分等工具辅助优化；ATS工具也在个人资料上传简历处提供，不限定于岗位进程 |
| 预览与导出 | 查看岗位简历并重新导出，用于官网上传 |
| 衔接网申 | 将当前岗位JD、个人资料和岗位优化简历提供给内置浏览器中的Agent |

ATS评分是本产品提供的简历优化辅助，不代表招聘方的实际筛选分数。JD支持投递前的简历修改；完整的字段、格式及附件要求以实际网申页面为准。

## 5. 内置浏览器中的网申辅助

J09直接在招聘网站上完成填写与检查。它与岗位工作台共享资料，不另建一套网申档案。

| 环节 | 行为 |
|---|---|
| 读取页面 | 识别当前表单字段、内容限制与附件要求 |
| 利用已有解析 | 网站提供简历解析时，利用岗位简历的解析结果，读取实际填入内容后继续检查和补充 |
| 辅助填写 | 依据个人资料、当前岗位JD及优化简历填写已有信息，辅助整理开放题内容 |
| 检查结果 | 检查内容合理性、格式、遗漏和解析错位；缺失事实或相互冲突的信息交给用户处理，不猜填 |
| 用户检查 | 先填写一版供用户检查、修改；最终投递后记录实际提交结果 |

岗位材料与网页填写可以往返：打开网申后发现新格式或附件要求，可以回到岗位工作台调整，再继续填写。填写完成不等于已经提交，执行过填写也不等于页面内容已正确保存，需要读取实际结果核验。

本阶段提供内置浏览器辅助填写与检查，不将批量自动提交或独立浏览器插件作为已确定功能。

## 6. 岗位上下文隔离

个人资料是共享基础；每个岗位的JD、优化简历、网申内容和其他岗位专属资料分别归属于该岗位。

针对岗位调整简历的经历选择和表达，保存为该岗位材料，不自动覆盖共享个人资料。若发现个人资料中的事实需要修正，沿用A阶段的提醒与用户决定机制。

| 当前工作 | Agent加载范围 |
|---|---|
| A岗位工作台或网申 | 按需加载个人资料＋A岗位JD、优化简历及相关资料，不加载B岗位资料 |
| B岗位工作台或网申 | 按需加载个人资料＋B岗位JD、优化简历及相关资料，不沿用A岗位资料 |

同一岗位内，工作台与浏览器共享岗位上下文；切换岗位时，Agent上下文一同切换，不能仅切换界面而继续携带上一个岗位的资料或对话内容。J06的跨公司、跨岗位检索结果不自动成为每个岗位工作台的上下文。

用户主动选择多个Offer比较时，按[D阶段的比较任务范围](D-offers-and-closing.md)读取所选Offer的比较资料，不默认读取全部岗位对话；返回单岗位工作时恢复该岗位范围。
