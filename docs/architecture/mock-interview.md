# 模拟面试架构

> 状态：现行专项实施说明；不定义产品或目标架构
> 上位规范：[`career-agent-os-blueprint.md`](./career-agent-os-blueprint.md)

## 产品形态

当前版本是“文字对话 + 可选录音转写 + 面试官 TTS”。文字输入和录音输入是
平行入口：录音只上传一次，服务端在同一个接口中完成转写并保存原声，用户可以
修改转写文本后再提交回答。TTS 失败时保留文字内容，不影响继续面试。

实时双向语音属于后续独立升级，不在当前链路中预埋另一套状态或兼容分支。

## 启动与逐轮生成

启动入口共用 `MockPreparationRequest`：个人简历 ID、JD 文本或精确版本引用、
文字/语音模式、面试官风格、可选岗位关联和预计题量（15/20/30，默认 20）。开始时模型基于简历与 JD 为固定四阶段生成本场考察指导；它不是题库，
也不规定每阶段题数。

每一轮面试官生成都读取：

- 本场个性化阶段指导；
- 当前阶段；
- 完整已持久化对话；
- 候选人的最新回答；
- 是否达到预计题量提醒。

阶段按能力覆盖和当前回答的信息增益自然推进。预计题量只提醒模型控制节奏，既不
截断当前讨论，也不强制结束。模型只在候选人反问阶段确认没有更多问题时建议收尾；
真正结束始终由用户确认。

## 数据职责

| 数据 | 唯一职责 | 生命周期 |
| --- | --- | --- |
| `interview_records` | 面试与复盘的持久状态、简历/JD 快照 | 长期 |
| `conversation_messages` | 完整面试对话与每轮阶段标记 | 长期 |
| `mock_interview_runtime` | 活动面试的计划、当前阶段、当前问题、回答领取和节奏游标 | 仅活动期间 |
| `interview_qa` | 统一批量分析产生的逐题结果 | 复盘生成后长期 |

每个用户最多有一个 Runtime。复盘任务成功进入队列后，Runtime 与其中的个性化
计划立即删除；若派发失败，记录恢复为 `mock_in_progress`，Runtime 保留，用户可
直接重试结束。`InterviewRecord.status` 是唯一持久生命周期状态。

## 复盘与质量门禁

模拟面试和上传录音复盘共用同一套批量 QA 分析。模型负责逐题证据与总结，代码
负责分数聚合，并区分低分与未考察。

发布前的模拟面试评测同时覆盖单轮和完整轨迹，包含阶段覆盖、重复追问、Python
知识穷举、低价值深挖、题量提醒、提前结束、提示词注入、反问事实约束、语言切换
和断线恢复。结构门禁还要求收尾消息只能提示用户结束，不能声称面试已经结束。


## 审查分支的统一启动合同

`MockPreparationRequest` 是 HTTP 和 Agent 工具的共同输入合同。新请求默认 `input_mode=text`，只有 `voice` 才检查麦克风；语音失败后可以明确选择文字降级，不重复创建 Runtime。历史未携带模式的 ClientAction 保持原有 voice 解释。
JD 可直接输入（20–50,000 字符），或引用精确的 owned `jd_snapshot_id + jd_snapshot_version + job_opportunity_id`，两种入口互斥。服务端解析并冻结内容后再交接，不能把当前最新 JD 偷换成用户指定版本。
Agent 的预填页面只确认本次冻结设置。其按钮提交 ClientAction 回执，不调用第二次 `/mock/start`；真实 Runtime 仍只由 `mock_flow.start_mock` 创建。页面回执和 Runtime read-back 继续分开。


## 回答的短事务、租约与迟到结果

`mock_flow.submit_answer` 在 Phase A 中锁定面试生命周期、领取当前问题、保存候选人回答，
然后提交并释放数据库连接。传入模型的是已冻结的标量和对话快照；提交后不再读取失效的
ORM 属性，否则会隐式启动跨模型等待的事务。Phase B 按同样的 Interview→Runtime 顺序
加锁，并校验当前问题和 `answer_claim_generation`，再原子保存下一问及游标。

迁移 `0051` 增加单调递增的代次，保留原 Runtime 和对话。租约过期允许接管，但不允许
旧请求发布结果，也不允许旧请求的超时/取消清理释放接管者的租约。结束或删除面试后，
迟到的模型结果不能将其恢复到进行中。该保护不等于撤销远端模型请求，也不保证模型不计费。

同一问题已有尚未回应的回答时，只能核实或使用同一份文本重试，不能把另一个答案借用旧
问题身份追加进去。录音仍通过原有附件生命周期保存；刷新恢复不再重复消耗已消费的录音。

## 可解释的失败与重试

- 首次回答请求失败后，页面只 GET 已持久化现场。若下一题已提交，直接采用它；若回答
  已保存但下一题缺失，提示用户“重试生成下一题”，明确可能产生额外模型费用。
- 重新连接与页面刷新不会自动 POST 生成；恢复到尚未回应的回答时禁止覆盖，却仍允许
  用户结束并生成复盘。放弃请求失败不会把未完成面试从页面列表中伪装删除。
- 完整返回但 JSON/业务合同无效的生成结果可修复一次；连接中断、超时或未知响应不自动
  重发。应用包装器不再启用额外的隐藏重试。
- 下一问必须为1–800字符的完整字符串，阶段只能停留或前进到相邻阶段，结束建议必须为
  JSON布尔值。程序不通过截断字符串或重写非法阶段掩盖模型错误。
- 已持久化的长回答不再只传前2000字符。模型请求先计入完整对话和输出预留；必要资料
  超窗时明确失败并保留回答，不静默删掉尾部限制。Token估计仍不是供应商精确计费。

生产实现由服务/API/页面共用；回归入口为 `test_mock_flow_phase5.py`、
`test_mock_answer_fencing_postgres.py`、`MockLive.test.tsx` 和真实浏览器测试。
浏览器中的计划、失败和下一问来自明确标注的离线模型替身，认证、HTTP、SQL事务、领域
操作和正式构建的前端都是真实代码；不能把这些结果写成面试官语义质量或学习效果成绩。
