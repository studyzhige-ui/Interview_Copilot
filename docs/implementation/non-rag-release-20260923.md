# 非 RAG 优化提交记录（2026-09-23）

本次提交将已实现的非 RAG 优化从混合工作区拆出，基于 GitHub `main` 独立验证。RAG 检索、向量存储替换、Qwen 模型接入、RAG 数据集和评估结果不在本次提交范围内；向量索引仍沿用 main 的 Milvus 实现。此记录是工程回归证据，不代表完整产品评估或生产环境验收。

## 根因与修复范围

| 问题根因 | 本次修复 |
| --- | --- |
| 刷新令牌消费缺少数据库级唯一约束，撤销状态依赖 Redis | PostgreSQL 持久化撤销和原子消费；前端合并并发刷新、协调跨标签页刷新并防止退出后的迟到响应恢复登录 |
| 异步客户端跨事件循环复用，同步数据库操作占用异步执行路径 | 客户端按事件循环持有和关闭；Celery 复用受控事件循环；调整同步路由和 Session 生命周期 |
| Turn 取消只依靠瞬时传输信号，终态通知与提交次序不一致 | 持久化取消请求、区分排队与运行超时、提交终态后通知，Redis 异常时恢复终态读取；前端恢复服务端记录 |
| Outbox 过期执行者可能覆盖新执行者结果 | 不可变执行快照、租约版本 fencing、续约和带所有权约束的结算 |
| Agent 和记忆任务缺少完整资源与生命周期边界 | Agent 时间和 token 预算；记忆输入输出上限、保留期清理、来源有效性复查和过期反馈拒绝 |
| 用户缺少清晰的手工面试录入和近期活动入口 | 手工邀请表单与今日活动展示，补充相应前端回归测试 |
| 备份对象路径缺少约束，恢复可能部分成功 | 校验对象路径位于目标目录内；数据库恢复启用错误即停和单事务 |
| 数据库模型与历史迁移存在结构差异，数据库测试可能被跳过 | 结构对齐迁移与真实 PostgreSQL 并发测试；CI 显式配置测试数据库，配置存在但连接失败时不能静默跳过 |

## 数据库升级注意事项

发布迁移链为 `0046 → 0049 → 0050 → 0051 → 0052`。编号间隔有意保留，未发布的 RAG 迁移不属于此链。后续 RAG 方案必须以已发布的最新 head 为基础编写后继迁移，不能将迁移插入已发布链中。

执行迁移前备份数据库并停止 API/worker 写入。`0049` 切换令牌撤销的权威存储并递增现有用户的 token_version，因此现有会话需要重新登录；回滚不会恢复旧令牌有效性。

## 验证与边界

验证在独立工作树执行，使用该树安装的依赖、独立 PostgreSQL 与 Redis。前端使用锁文件对应的已有依赖。后端验证覆盖迁移升级、结构一致性、真实数据库竞争以及完整单元测试；前端覆盖测试、类型、Lint 和生产构建。

验证结果：

- `alembic upgrade head` 和 `alembic check` 通过，未检测到结构漂移。测试还验证 `0052` 降级再升级、8 个并发事务争抢同一个刷新令牌仅一个成功。
- `ruff check backend/app backend/tests evaluation scripts` 通过；`ruff format --check` 检查的 646 个文件全部通过。
- `pytest backend/tests --ignore=backend/tests/test_rag -q -rs`：1465 通过，1 跳过，43 条警告。跳过项是未下载发布语料的 RAG 数据集检查，不是数据库测试。
- 完整 `pytest backend/tests -q`：1594 通过、2 跳过、1 失败。唯一失败项为未修改的 `test_rag/test_chunking.py::test_code_uses_language_parser`，原因是 `tree_sitter_language_pack.DownloadError`（下载超时）。另外一个跳过项需要在线 Milvus 与 reranker。没有修改或屏蔽原有 RAG 测试。
- 前端 60 个测试文件、192 项测试通过；类型检查、Lint 和生产构建全部通过。

上述后端验证使用 Python 3.13；Python 3.11 由仓库 CI 后续验证。警告主要来自测试用短 JWT 密钥和部分 SQLAlchemy 测试事务夹具，未将其描述为零警告通过。第三方模型在线质量、生产负载容量、完整端到端用户验收和 RAG 发布质量不能由这些回归检查替代。本次不新增完整评估体系。
