# 页面布局与加载排查（2026-09-17）

## 根因与修改

| 范围 | 发现 | 修改 |
| --- | --- | --- |
| 模拟面试准备页 | `h-full + items-center + overflow-y-auto` 将超高表单居中，顶部可能落入负方向、无法滚回 | 移除固定高度和内层滚动，由 AppShell 的 main 统一承载自然高度内容 |
| 全站切页 | main 是真实滚动容器，但路径变化时没有重置它 | pathname 变化重置 main.scrollTop；同页 query 参数变化保留滚动位置 |
| 求职进程 | 每次进入立即请求 8 组数据，整页还等待行动接口 | 空账户初始只取岗位和行动；重复检查、材料、面试和 Offer 在相关窗口打开时取；档案按展示/编辑需要取 |
| 求职进程 | 次要接口慢或失败会挡住岗位主体 | 岗位独立展示，行动区域拥有独立加载/错误和重试反馈 |
| 资料库 | 文件与分类绑在 Promise.all，文件轮询还重复拉分类 | 两个独立查询，分类慢不挡文件；仅处理中文件触发文件查询轮询 |
| 能力成长 | effect 每次挂载重新请求；StrictMode 可重复请求；没有共享查询缓存 | 接入已有 React Query，复用 30 秒新鲜数据，保留显式刷新 |
| 全局字体 | CSS @import 外部 Google Fonts；正文 TTF 为 1,240,844 字节 | 等宽字体使用系统字体，删除外部 CSS 依赖；Inter 改为 WOFF2，386,960 字节，减少 68.8% |
| 全局鉴权 | refresh 请求绕过带超时的 apiClient，没有超时上限，其他请求等待同一 refresh promise | 为 refresh 设置 10 秒超时，保留已有并发合并和登录失效处理 |

字体由现有本地 TTF 转换，保留原文件；已核对 glyph 顺序和 Unicode cmap 相同，不引入应用运行时依赖。

## 排查证据及范围

- 审查了共享 AppShell、路由 lazy/Suspense、API 客户端、求职、模拟面试、资料库、能力成长、今天、个人档案、材料及行动决策的数据获取方式。
- 当前数据库仅 1 个用户样本。只读服务调用连同列表序列化：岗位 5.59 ms / 1 条 SQL，行动 4.19 ms / 1 条 SQL，重复候选 5.21 ms / 2 条 SQL。没有对产品数据做写入。这不是大数据量压测，也不是浏览器端到端耗时。
- 岗位服务已经有分页上限及 direction_links 的 selectinload，本次没有依据不足地改数据库索引或增加缓存。
- HTTP health：`127.0.0.1:8080` 约 4.7 ms，`localhost:8080` 约 216 ms；前端代理入口分别约 5.8 ms / 221 ms。本机 localhost 建连存在约 200 ms 差异。没有切换用户浏览器 origin，以免影响原有登录存储。
- Vite 热缓存下，四个页面模块响应约 2–33 ms。这不能说明首次冷加载也同样快。
- 当次 Google Fonts CSS 请求约 301 ms。移除外部样式依赖消除了这条首屏网络链路，但没有据此虚构完整页面提速倍数。
- 生产构建保留按路由拆包：CareerProcessPage gzip 9.14 KB，MockPage 10.62 KB，LibraryPage 5.60 KB，AnalyticsPage 2.61 KB；这些是页面自身分块，不包含共享依赖。

## 验证

- `npm run build` 通过（包含 TypeScript 检查）。
- 全前端 **57 个测试文件、183 项测试通过**。
- 修改的 TS/TSX 文件 ESLint 零警告；本次已跟踪文件 diff whitespace 检查通过。
- 新增行为测试：切页滚动重置与同页筛选保持；行动接口未返回时岗位仍显示；空账户不预取窗口资料；打开窗口后按需取数；分类接口未返回时文件列表仍显示；能力页 StrictMode 请求合并及返回缓存。
- 新字体通过正在运行的 Vite 返回 HTTP 200，实际响应 386,960 字节。构建 CSS 无 Google Fonts 依赖。
- 后端 ready，数据库与 Redis 为 ok；无需后台数据迁移。
