## WhisperX 长录音补齐

恢复点：`codex/checkpoint-before-whisperx-longform-20261011` / `46f7139`。
面试录音仍走 `transcribe_interview_evidence` → 不可变源快照 → 用量准入 →
WhisperX collector → 统一证据校验与发布。collector 复用 `PCMStream`，每个模型输入
最多 30 秒；核心区最多 26 秒，按 VAD 语音边界/min-cut 接续。未消费的样本留给下一核心区，
右侧最多 2 秒上下文，剩余窗口容量用于前文说话人上下文，避免短尾窗退化。PCM 内存有界。
输出文字和轨道继续受既有容量上限约束。解码沿用 Linux/WSL2 worker 的现有执行边界。

WhisperX 复用已加载模型的时间戳解码入口，消费全部解码片段，再逐核心区 forced alignment。
每个 PCM 样本只属于一个转写核心区，按原始偏移接续，保留标点、空白、置信度及未知对齐。
重叠音频只用于说话人观察；删除重复转写后猜词去重的旧拼接算法。时间、文本覆盖、容量、
身份与完整解码的校验仍然保留；时间越出核心区会失败。
Community-1 每窗的说话人向量映射到录音内固定身份；局部标签可交换，身份锚点不漂移，
歧义会报错。匹配阈值沿用原显式策略，尚无真实录音校准结论，不是身份识别概率。
每窗允许一位说话人，配置的最少人数在整段结果检查，最多人数同时约束窗口和整段。
不完整解码、模型变化、容量超限、取消都不发布部分成功；仍由原用量与源快照所有者收尾。

真实模型验证补齐了两个接口细节：WhisperX 的 NumPy 时间/置信度数值在提供者边界严格
校验后转为标准浮点数；对齐所需 NLTK `punkt_tab` 在本地模型镜像构建时准备，运行时
缺失会明确失败，不隐式下载。非容器环境需在启动 worker 前执行
`python -m nltk.downloader punkt_tab`。本机验证使用已缓存资源；未重建完整生产镜像。

类似遗漏复核：RAG、事件、上下文、文件上传、附件解析等待和用量读取均已找到当前承接路径；
旧用量 HTTP 合同已恢复。另确认本地 TTS/实时合成仍未被替代，`live_synthesis_unavailable`
是当前明确的能力缺口。本轮不更换其提供者。知识库普通音频和远程混合 ASR 的整段解码
不是原 Qwen 面试证据分窗的承接者；本轮修改的范围为面试录音证据入口。

## 121.6 秒录音根因修复

修复前检查点：`codex/checkpoint-before-whisperx-coverage-fix-20261011` / `3ea37f0`。
原先的“拒绝发布”只阻止了错误结果，不能算功能完成。本次沿完整录音复现并修复：

- 50–80 秒窗口的 Pyannote VAD 保留了五段语音；WhisperX 无时间戳批量解码将其合成一块，
  只返回首句。最后一窗同样只返回末句。故障在解码输出，不是 FFmpeg 漏样本或 VAD 漏段。
- forced alignment 把不完整文本放入整窗时间范围，末句被错误放到 102 秒附近。
  固定边界还会切断词语，使重复识别的两份重叠文字产生冲突。缩短批量解码粒度虽找回
  更多文本，仍有重叠区冲突，因此没有保留这种参数补丁。
- 复用 `_transcribe_with_word_timestamps`，以 VAD 边界划分不重叠的核心区，完整消费
  时间戳解码结果；说话人仍观察重叠窗口。两种职责不再共用同一个固定转写切点。
  普通本地转写无论是否启用说话人分离，也统一使用该入口，移除原有无时间戳解码旁路。
- 短尾窗不足以稳定说话人向量时，用窗口剩余容量保留前文，而非降低相似度阈值。
  Pyannote 的补齐分析帧通过原生 `Annotation.crop` 限定在真实音频范围，之后仍走原严格合同校验。
