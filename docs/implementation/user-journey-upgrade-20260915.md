# 新用户与协作恢复升级验收

## 目标与边界

从首页明确目标，进入对应协作，保留输入和执行身份，离开后能找到原任务。已有领域服务继续负责岗位、行动、材料和面试数据。本次没有数据库迁移，没有移动或改写 product-rebuild，也没有改动外部迁移后的 CareerOS 项目。

## 已确认的原因及改动

| 原因 | 改动 |
| --- | --- |
| 没有数据时首页仍显示多个空区，缺少可执行的第一步 | 首页通过 `/api/v1/workspace` 读取真实材料、机会、行动和最近协作；无机会、无行动时显示三个具体起步目标 |
| 页面入口丢失用户目的，返回协作时总选最新会话 | 使用 `start` 选择可编辑起步草稿、`session` 明确指定会话；草稿必须由用户发送 |
| 新建会话响应丢失后重试可能创建多个会话 | 可选 UUID 请求编号，由后端结合用户身份生成稳定会话 ID，重复和并发请求返回同一会话 |
| 记录读取失败被当成空会话 | 显示错误与重新加载入口；成功读取历史前禁止发送 |
| 停止请求失败仍清除本地任务身份 | 仅在服务端停止成功后清除；失败保留订阅与原任务身份 |
| 连续 SSE 提前关闭最终被当成完成 | 没有收到完成事件就抛出断线状态，原任务可重新连接 |
| 发出消息立即清空输入，响应不确定时无恢复依据 | 保留原请求编号、正文、附件引用、模式；同一标签 sessionStorage 支持刷新恢复；确认送达使用同一请求，不生成新任务 |
| 队列读取失败被静默忽略，模型未配置也可点击发送 | 显示队列状态过期和刷新入口；模型配置读取/能力校验未通过时明确提示并限制发送 |
| 求职页零数据仍铺开大尺寸列表、详情、行动框 | 零数据时显示单一添加岗位入口和求职方向协作入口；已有行动仍保留展示 |

## 数据和执行约束

- 首页是读取投影，不创建另一套任务状态或首次使用标记。
- 首页最近协作仅查询当前用户未归档的 general 会话，最多五条；状态来自各会话最新持久化 Turn。完成只表述为“本轮已结束”，不推断求职目标完成。
- 读取失败不伪装成零数据。起步草稿不自动发送，不自动上传附件或保存材料。
- 断流后的恢复订阅已有 Turn；未确认送达时重用已有 Submission 标识和冻结的输入。
- 浏览器禁止存储时，未确认输入只能保留在当前页面内存。sessionStorage 不用于跨设备同步。
- 新建会话请求标识目前跨同一页面的手动重试有效；刷新页面后重新点击新建会产生新请求。既有会话仍可从记录列表恢复。

## 验证证据

- 前端构建成功，ESLint 通过，53 个测试文件、176 项测试通过。
- 后端 workspace、chat API、turn executor 相关 64 项测试通过，使用独立 SQLite 测试库。
- 覆盖用户数据隔离、最新轮次状态、创建请求重复回放、指定会话导航、起步草稿、不确定发送原编号重试、刷新恢复、停止失败、SSE 无完成事件。
- 正式代理 `/api/v1/health/ready` 返回 200；未登录访问 `/api/v1/workspace` 返回 401。
- 浏览器使用明确标记的验收数据检查了首次使用页面布局，临时验收入口已移除。

## 尚未验收

当前内置浏览器停留在登录页，已请用户自行登录。真实账号下“上传资料 → 模型工具执行 → 用户确认 → 保存材料 → 刷新后继续”的完整流程尚未执行，因此这些改动不构成全套协作能力或所有外部服务已经可靠的证明。

模型密钥有效性、模型实际回答质量、真实文件解析、第三方邮件及插件需要分别进行真实业务验收。没有改动 Gmail 发件配置，没有发送测试邮件，没有提交或推送代码。
