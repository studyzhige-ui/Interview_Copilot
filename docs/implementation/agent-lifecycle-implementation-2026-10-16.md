# Agent 生命周期优化交付：2026-10-16

本轮在前一份生命周期审计基础上继续修改产品代码。范围由 Interview Copilot 已有的 Chat/Agent、工具账本、上下文投影及经验记忆决定，没有新增通用 Agent 平台、第二套记忆库或替代执行器。

## 已落地的行为变化

| 问题 | 修改后的行为 | 主要实现 |
|---|---|---|
| 长任务起始召回的记忆在编辑/撤回后仍留在后续请求中 | 每次 Agent 模型尝试及 Chat 最终请求前重新检查账户/会话开关、条目版本、状态、来源和保留期限。只移除失效快照，不偷偷把新版本当作已选择的经验 | `memory/recall.py`、`context_compactor.py`、Chat/Agent strategy |
| 只从当前消息移除记忆，压缩时仍可能从初始上下文重新注入 | 同时更新当前消息和压缩恢复使用的 initial_context；旧格式没有版本身份的块不继续使用 | `ActiveTurnContextReducer.revalidate_memory` |
| 用户已取消但轮次尚未终止，仍可申请下一次模型调用 | 准入必须为 running 且没有 cancel_requested；pending/waiting/已终止轮次均不能发起新模型调用 | `model_dispatch_service.start_model_dispatch` |
| 压缩重试倒退步数，后续循环复用模型调用身份 | 同一步内增加 attempt，下一步正常递增；删除无调用者的 refund_step | `agent_strategy.py`、`react_agent.py` |
| 旧任务计划不断追加，模型同时看到多个“当前计划” | 动态计划只保留最新投影；计划消失时清除，压缩不能恢复旧状态；不改写用户原始任务 | `context_compactor.update_runtime_state` |
| 未知异常默认重试，错误正文可混淆状态分类 | 先看 HTTP 状态，未知异常停止自动重试；403 正文出现 429 不会触发重试。已不确定的模型调用仍由账本阻止重放 | `retry_utils.py` |
| 最后一次超限失败后仍执行无用压缩 | 没有剩余尝试时直接传播错误，不再花钱压缩一个不会发送的请求 | `call_with_retry` |
| 重试日志原样输出供应商错误内容 | 日志仅保留异常类型、尝试次数和退避时间，避免把请求片段或敏感错误正文写入日志 | `retry_utils.py` |
| 用户确认有帮助，但模型没引用，记忆仍只按未使用处理 | 当前有效版本的 helpful 反馈更新保留依据；使用 receipt 的原始时间保证重复 PUT 不无限续期。引用计数保持独立 | `memory.recall.set_feedback` |

撤回不能撤销已经发送给供应商的请求，也不能删除模型已经输出的历史文字。本轮保证的是后续请求边界不继续携带失效的独立记忆投影。校验和远端接收不可能组成跨系统原子事务，不能把它描述为瞬时远端擦除。

## 验证已从函数测试推进到真实调用链

1. 完整 `AgentLoopStrategy.execute`，使用实际 registry、目录、参数校验、策略、工具执行账本、模型调用账本和完成检查；仅替换模型和合成工具的外部行为。
   - 工具成功后，下一次模型输入必须包含真实结果，才生成最终答案。
   - 工具返回失败及修正参数后，模型下一步按结果改变参数再调用。
   - 以上两种场景都组合了首次请求超限、压缩回调和重试，检查步骤与调用身份不重复。
2. 同一 Agent 多次模型请求之间修改记忆，覆盖未变、改版、停用、账户关闭、会话关闭、来源失效和过期；同时检查压缩恢复不会复活旧记忆。
3. helpful/unhelpful、旧版本、过期来源、其他账户五类反馈测试；不虚构模型引用，不凭旧反馈恢复过期记忆。
4. 模型准入检查 pending、waiting、请求取消、已取消状态；拒绝时不创建模型调度记录。
5. 错误分类和最后一次压缩边界测试，包含错误正文敏感标记不进入日志。
6. 真实模型记忆回答评测从内部 worker/native-wire helper 改为正式 `ChatPipelineStrategy` + 默认 primary（本次 deepseek-v4-pro），包含请求前记忆校验。使用合成账户和独立临时业务库；未读取真实用户偏好。

## 成熟度判断与尚未证明的部分

工程成熟度体现在上述状态转换和故障边界可复现，而不是功能数量。这轮关闭了实际代码缺口，但没有保证所有生成内容永远正确：真实模型仍可能漏引记忆来源，也可能在比较通勤时把没有说明的口径当成单程。六个自动断言只检验列出的行为，不是完整语义正确率。不能把记忆曝光或模型自述包装成用户收益。

目前的可讲述边界是：事实属于领域 owner，模型上下文是可替换投影，执行结果属于持久账本，记忆是带来源和版本的条件经验。失败、取消、更新和恢复都遵循这些归属，不靠复制更多框架代码维持一致性。

尚未执行的验收包括所有外部连接器的真实写入、多用户长时间压力/进程故障注入、真实用户任务收益统计，以及此次代码的运行服务发布验收。已运行的隔离代码测试不等于生产部署完成。没有改动正在运行的 `/app`，没有提交或发布其他工作区改动。
