## 已完成的用户流程

| 模块 | 实际行为 |

| 岗位详情 | 职位描述及历史版本、联系人与备注、求职方向、下一步、进展记录与说明更正、可撤销重复合并、面试与材料入口 |
| 简历与材料 | 独立文档库、从个人档案创建、文件与 JSON 导入、岗位专用副本、默认简历、归档恢复、原文件下载与替换 |

| 投递 | 明确记录发生时间、渠道、确切材料版本；流程事实与材料快照在一个事务中保存；后续改简历不改变历史投递 |
| 日程 | 面试安排与改期、用户行动、Offer 回复期限、月历/小屏列表、ICS 导出；行动与通知沿用既有服务 |

| 统计 | 当前阶段分布与历史漏斗分别呈现，保留月份/渠道/材料分组与数据范围说明 |

## 数据与并发设计

`0077` 为正式版本增加结构化文档，增加岗位备注/联系人及草稿侧表。`0078` 增加可重放的当前阶段投影及联合索引，并绑定草稿重试与发布来源修订号。主键、既有正式版本和流程事实保持不变。

同一岗位的当前阶段由唯一的有效事件重放逻辑产生，数据库直接筛选、统计和分页；列表仅聚合当前页的行动与面试。岗位归档与申请结束分别处理。更正旧阶段说明保持其原有流程位置，不把它重新当成当前阶段。

草稿保存使用修订号与基准正式版本做并发控制，同一次网络重试不再增加修订。正式发布绑定草稿修订，重试不重复建版本。发布期间禁止继续编辑。冲突时保留本设备内容，展示服务器内容，用户明确选择后再继续；文件提取完成前禁止覆盖原件。正式简历清空后取消默认与可用状态，避免面试继续读取失效内容。

## 使用与边界

本地验收入口：`http://127.0.0.1:18080/career-process`。代码已写入当前项目，本轮只更新独立 Docker 验收环境，没有部署到线上。原工作区未提交修改通过 `refs/checkpoints/career-redesign-20261015` 保存，检查点提交为 `a5b04d517a213465182249eb2431cc8242d0dc7d`。

- PDF 渲染器为延迟加载约 444 KB gzip 的独立模块，完整中文字体约 10.6 MB，仅预览/导出时加载。构建仍提示该独立模块超过 600 KB；没有通过调大警告阈值掩盖它。
- CSV 是岗位清单交换，导入预览明确只接收公司、岗位、地点、链接，统一保存为待投递；不导入阶段、备注或投递历史。不能把它当作完整数据库备份。
- 历史漏斗按每条岗位首次有效投递计算，保留合并来源；再次投递不新增样本。新投递用当次材料版本，旧数据的材料覆盖只能到岗位级，界面明确说明这一限制。
- 沿用既有 Copilot、通知与真实模型链路；本轮没有重新验收真实模型输出、外部邮件送达或完整发布矩阵。测试中的模型/外部依赖使用既有替身或跳过条件。
- 既有 npm 审计报告保留在本地验收目录，未在这次求职重构中擅自升级其他模块的大版本依赖。
