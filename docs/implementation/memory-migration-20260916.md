# 记忆生命周期迁移交付记录

日期：2026-09-16。授权：完整迁移 Codex 记忆机制；允许为此重构相关系统。

## 根因与修复

| 原问题 | 已实现修复 |
|---|---|
| 固定反馈词筛选、只有单轮文字 | 基于完整目标轮的有界上下文；读取真实 Tool Call 结果；结构化观察结果与精确来源校验 |
| 提取后直接覆盖同 key 的长期条目 | 提取结果与长期投影分离，第二阶段跨来源整理与冲突校验 |
| 模型异常等同“没有记忆” | 持久 succeeded / no_output / failed 状态、退避、可回收租约与定期补扫 |
| 只用关键词重合召回 | 简短索引语义选择，再取正文和来源；读取后重查权限、状态和版本 |
| 召回次数被当成效果 | 读取、回答引用、用户反馈分别记录；来源链接可以回到设置中的经验 |
| 删除来源后派生内容可能残留 | 清除提取与整理副本、撤销正在发布的租约、保留无正文抑制身份，剩余来源可重建 |
| 未校准的 0.75 模型自评分门槛 | 真实模型给有依据经验评分 0.6；改为来源和观察结果准入，保留置信度而不将自评分当作真值 |
| 引用网页内容被误概括成经历 | 增加 user_reported_result / verified_tool_result / unverified 契约，未验证内容不准入；评测覆盖此回归 |

旧关键词召回与单阶段提取/覆盖代码已经退出生产路径。用户管理接口与现有唯一用户级长期记忆集合保留。

## 本地部署结果

- 数据库已经升级到 `0044`。升级前后现有长期记忆记录数均为 0；迁移的非空保留能力由独立 PostgreSQL 用例验证。
- 本地 `.env` 的部署级 `AGENT_MEMORY_PRODUCER_ENABLED=true`。账户与会话的贡献选择未更改，仍需用户自行允许。
- 后台任务已注册到 jobs / turns 两个具名 worker；Beat 已实际派发并完成 memory discovery。模型后台工作路由到 background 队列。
- 启动脚本为两个 worker 指定不同节点名称，并更新就绪匹配，避免默认同名 worker 导致状态观察混淆。
- 查明本机 `localhost` Redis 首次异步连接耗时约 2.047 秒，超过 2 秒健康检查；明确 IPv4 回环后约 0 秒。本地连接地址已修正。
- 最终 API `/api/v1/health/ready` 返回 200，database / redis 均为 ok；未登录访问记忆 API 返回 401。当前 API 用普通 uvicorn 进程运行，后台 worker 与 Beat 由启动脚本维持。
- 使用入口：`http://localhost:5173/settings/personalization`。可管理记忆、查看来源、观察整理状态和提交有帮助/没帮助反馈。
