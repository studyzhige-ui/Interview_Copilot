# Local finite TTS: production broker path, not streaming acceptance

## Delivered boundary

The existing mock-interview speech endpoint now selects local Qwen3 CustomVoice
by default and returns a WAV with its real content type. It reuses the existing
broker, model processes, admission, cancellation and usage-accounting operation;
there is no API-process model load or second inference service. Edge is retained
only for explicit `TTS_PROVIDER=edge` legacy deployments and is refused under
local-only policy. Missing local weights/socket never switches provider.

Qwen3-TTS-12Hz-0.6B-CustomVoice is a **preset-voice candidate**, not a claimed
quality winner over the previously proposed CosyVoice candidate. It provides a
finite local speech path without requiring a reference/voice-cloning recording.
This does not select the final streaming engine before device evaluation.

The versioned adapter requires `qwen-tts==0.1.1` in an isolated interpreter. It
uses that wrapper's codec-generation boundary: budget-adjacent code sequences
are rejected before waveform decode, then sample rate, mono shape, finiteness,
amplitude and output size are validated. This is a conservative token-budget
guard, not proof that every spoken word matches the input or a model-quality
measurement. The high-level SDK call does not expose a termination reason.

The IPC envelope binds text hash, voice, language and the broker's model/revision
binding to 24 kHz signed-16-bit PCM. Input is at most 600 characters; output is
at most 60 seconds and fits the unchanged 4 MiB protocol. Invalid or excessive
output is rejected, not clipped to look successful. The final WAV is also
subject to the application byte budget. Generation is NOT delivered/heard audio.

HTTP authentication remains required. The authentication database session closes
before model work. Output is no-store/nosniff, and unavailability/uncertain
execution are explicit errors with no automatic request retry. The frontend's
existing cancellation/playback identity fence continues to apply to this blob.
The setup page now uses deployment-default voice unless a local preset is
explicitly selected. Old Edge localStorage preferences are not silently mapped
onto a local voice. The 600-character bound is surfaced without truncation;
legacy Edge deployments use the deployment-default choice.

## Explicit preparation, deferred until model/device acceptance

`requirements/local-tts.txt` belongs only in the chosen isolated TTS environment.
No installation or model download happens during API startup. At final setup,
`prepare_local_inference.py --tts-python <venv-python> --tts-model <model-id>` adds
one synthesis role to the same broker. The existing RAG/audio configuration
arguments still apply. It refuses missing weights or a local speech tokenizer
that is absent from the verified snapshot manifest; path existence is not model
readiness. `MODEL_REVISIONS_JSON` must match the broker and snapshot.

Application configuration must agree with that explicit broker selection:

```
TTS_PROVIDER=local_qwen3_tts
TTS_MODEL=Qwen/Qwen3-TTS-12Hz-0.6B-CustomVoice
TTS_DEFAULT_VOICE=Vivian
TTS_LANGUAGE=Auto
```

The 4000 MiB reservation is admission policy, not measured VRAM. Neither model
co-residency on 16 GB, CUDA/Torch compatibility, language quality, first-audio
latency nor actual speaker output has been accepted. WebRTC, streaming TTS and
semantic turn ending remain separate work. The SDK's `non_streaming_mode=False`
is not used as a substitute for a real streaming transport.
