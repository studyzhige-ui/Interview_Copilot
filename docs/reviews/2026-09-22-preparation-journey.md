# Version-bound preparation, source review and focused practice

The mock setup now provides an explicit, read-only preparation preview using
saved resume content and either an inline JD or an exact owned JD snapshot.
The HTTP route and the Copilot `prepare_interview_evidence` tool invoke the same
application operation. No model request or profile mutation occurs during
preview. Users can inspect exact source offsets, export Markdown notes, inspect
an extractive resume preview and explicitly start practice on one selected JD
passage. The original resume is never overwritten and no experiences or numbers
are generated by the extractive view.

The preview returns the exact resume ArtifactVersion, canonical text SHA-256,
JD text SHA-256 and original source identities. The UI and Copilot carry these
fences into the existing start operation. A newer resume version or changed
canonical text/JD rejects before model planning or interview creation; it is not
silently replaced with a new source. Existing callers without a preparation
preview may still start normally. Frozen interview sources remain the existing
canonical source of the run after admission.

Lexical overlap locates candidate evidence only. It does not prove that a
qualification is met, diagnose a skill gap, provide a semantic fit score or
certify an experience. The UI and export say this explicitly. No overlapping
passage means "evidence not located", not "candidate lacks skill". Model-led
questions/feedback still use the existing interview planner and rubric; their
quality needs the planned local/provider evaluation.

Every nonempty source passage is bounded and visible through pagination. Long
physical lines are partitioned with exact offsets; an excessive number of
passages fails explicitly rather than silently truncating the input. Client
source changes abort requests and prevent late previews from replacing current
input. Starting a drill is an explicit action, not a side effect of preview or
export. Source-conflict messages are presented instead of a generic start error.

The existing `read_resume` tool now returns coverage, next_offset, version and
text hash. Reading later pages requires all source pins. It no longer makes an
18,000-character prefix look like the entire resume. A changed version or parse
result fails rather than joining pages from different documents.

Tests exercise exact quoting, ownership, archived sources, immutable artifacts
and profile counts, stale source rejection before model calls, schema pairing,
HTTP/application agreement, source-change cancellation and the preview-to-drill
UI. Shared contracts are generated using the locked Python/OpenAPI/TypeScript
pipeline. These deterministic tests are not model-quality or device acceptance.
