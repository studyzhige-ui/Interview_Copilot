# M3 定向实验退步原因复查

本次为诊断，不选新参数，不修改应用，不做答案生成，不新增API调用。
验证集已被用于本轮事后分析，因此不能继续称为未触碰的验证集；后续改动需要新的独立评估数据才能确认泛化收益。

## 1. 全量450题的事实

| 新方案相对原基线 | 数量 |
|---|---:|
| nDCG@10改善 | 69 |
| 不变 | 290 |
| 退步 | 91 |
| 退步且原问题与改写文本完全相同 | 20 |
| 退步且前10出现新增、未标为正例的候选 | 79 |
| 退步且至少一个原有正例掉出前10 | 29 |
| 扩候选后增加了标注正例候选 | 77 |

后四项存在重叠。nDCG退步并不一定意味着正例完全掉出前10，也可能只是位置降低。
新增未标为正例的片段不能直接等同于不相关内容。

## 2. 三步改动在659题调参集的独立影响

| 单步变化 | 改善 | 持平 | 退步 | 八单元宏平均nDCG变化 |
|---|---:|---:|---:|---:|
| 基线→保留两路并集 | 16 | 565 | 78 | -0.001357 |
| 再加入原问题召回 | 4 | 640 | 15 | -0.000058 |
| 再加入原问题重排 | 117 | 445 | 97 | +0.004964 |

调参集仅最后一步有总体收益，但有大量反向案例，且验证未复现。不能据此把全量原问题混入排序作为默认设计。

## 3. 原始分数与固定候选池复算

每个数据集/领域选择最大两例退步和最大一例改善，共24例。
重新对完整候选池计算原问题、改写问题的M3分数，固定分数后比较各个候选集合和排序融合。
此样本刻意包含极端案例，不能用样本占比估计全量原因分布；两套数据也存在重复对话输入。

### 已确认A：候选扩张改变了前10竞争，改写不是全部原因

`mtrag-human::5815bb4a99e2a0d8a986348da4c49083<::>7`：原问题和改写都是 `Explain Spark.`。

- 固定同一套重排分数，标注片段由第6/8位降到第12/14位。
- 仅保留更多候选就使nDCG从0.4118降至0；原问题召回和双重排没有进一步改变这个案例。
- 高位内容包含Spark代码样例。表明当前排序无法仅靠候选扩张自动选出标注需要的解释性证据。
- 短问题本身的意图充分性与标注范围仍需区分；本例不能证明所有新增候选都不相关。

### 已确认B：未消解指代的原问题被赋予了排序权重

`mtragun-human::3a44984a1b74e5be70f01e8a60c3ea14<::>2`：

- 原问题：`How many times is it there in the bible?`
- 改写正确补出了特定谚语对象。
- 扩候选和加入原问题召回均保持nDCG 0.7845。
- 在相同候选池加入原问题排序后，nDCG降至0.1413。
- 正确谚语片段从第1位降到第9位；讲Bible中alcohol提及次数的片段从第10位升到第1位。

根因在排序输入与融合设计：不完整原问题中的 `it` 没有对应实体，却被当成独立有效查询参与固定权重RRF。
这里不是改写失败。RRF也不会自动判断某一路查询是否语义完整。
类似的 `where to purchase those?`、`How can I apply?` 在固定候选情况下也只在双重排阶段明显退步。
不能据此制定“短句一律不用原问题”的规则，因为24例中也有短句受益案例。

### 已确认C：ID级标注与实际文本证据存在不一致

`How can I create one?` 的案例中，返回了明确描述注册IBM Cloud账户步骤的未标为正例片段。
这支持需要复核标注完整性，但本次没有自行改变相关性标签。

另对450题进行了独立的全量精确文本检查：仅规范空白后，11题的返回前10包含与某个标注正例全文相同、ID不同的片段。
其中原基线影响10题，新方案影响11题。详见 duplicate-evidence-audit.json。
这证明部分ID级零分具有标注覆盖问题，但数量和两方案差异不足以据此解释全部退步。

## 4. 工程记录问题及修复

上一轮验证文件仅保存最终排名，未保存原问题/改写两路独立分数，不能直接分解排序融合原因。
本次诊断补录两路分数、每个中间排名、原文和token长度，固定候选/固定分数进行复算。
新增探针脚本为 evaluation/mtrag/investigate_quality.py；原实验结果和标签保持不变。

## 5. 下一步边界

- 保留原基线；停用全量扩候选与无条件原问题双重排作为默认方案。
- 下一项检索修复应优先明确查询输入契约：保留用户显式实体，消解省略指代，识别话题变化；不把未消解的原问题直接交给重排作为独立依据。
- 用已确认的实体替换错误和本轮确认的正确改写案例组成相反方向的回归检查，防止修复前者时破坏后者。
- 保持官方qrels作为标准结果；文本等价及人工复核仅作为诊断旁表，不能偷偷替换评分标准。
- 输入截断是否是主因仍未证明，不继续因为长文本存在就增加长度预算。
- 不进入生成侧；本轮没有声称检索质量已改善。

证据文件：audit.json（全量轨迹与调参分步计数）、probe-results.json（24例分数/排名/原文）、duplicate-evidence-audit.json（文本等价检查）。
