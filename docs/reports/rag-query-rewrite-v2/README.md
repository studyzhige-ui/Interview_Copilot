# 查询改写 v2：提示词与重新改写

## 已实施

新增 `evaluation/mtrag/prompts/query_rewrite_v2_1.txt`，明确七类规则：当前信息需求与多意图保留、必要历史补全、当前实体与用户纠正优先、精确检索词保护、歧义与历史回答的事实边界、最小改写、输入数据与 JSON 输出边界。

模型及采样参数保持 DeepSeek `deepseek-flash`、temperature=0、thinking=disabled、max_tokens=512。提示词是本项目根据官方参考和已复现问题编写，不是厂商内部提示词。

旧版默认评测入口保留 v1，用于复现既有结果。此次 `rewrite_campaign` 明确使用 v2.1，独立输出到 `data/evaluation/mtrag/rewrite-v2.1/`。新请求的完整提示词参与缓存键，不能误用 v1 缓存。共享缓存仍在 `data/evaluation/mtrag/rewrites/`，相同输入不因题目 ID 或检索模型不同而重复调用。

## 全部上下文是否传入

是。本轮逐条验证了 1,109 条题目：

- 规范化输入与官方每条任务的完整 `input` 一致。
- API 请求中的历史 JSON 与上述输入一致；未只取最近几轮，未截断或摘要替换。
- 消息数符合官方轮次 `2 × turn - 1`；包括全部历史用户提问和助手回答，截止当前用户提问。
- 1,092 个唯一旧版请求均存在匹配的缓存指纹，说明旧版实际请求也是该历史输入。
- 最长 23 条消息，正文最长 9,292 字符；125 条为单轮问题。
- 不把当前参考答案、未来轮次、相关性标签和证据文档交给改写模型。

完整提供历史，与把全部历史细节写入查询，是两回事。模型应读完整可用历史，只携带理解当前请求所需的信息。已确认的实体替换失败发生在完整历史已提供的情况下，不能归因于漏加载历史。

## 验证

11 项离线契约测试通过，包括：完整长历史保留、早期消息改变导致缓存失效、v1 缓存身份保持、v2 与 v1 缓存隔离、禁止评测隐式调用 API、并发请求去重、已保存响应恢复、超时不重复调用、截断响应拒绝、禁止金标字段和当前答案进入输入。

4 个真实 API 诊断案例人工核查：

| 案例 | 新版结果 |
|---|---|
| 当前明确 server，历史讨论 key | 保留 server，没有替换成 key；对措辞做了轻微整理，并非逐字不变 |
| Bible 问题中的 it | 仍补出所指谚语，与旧版正确改写一致 |
| Explain Spark. | 原样保留 |
| 只有个人冰球经历的陈述 | 原样保留，不擅自创造问题 |

这些检查证明三个具体案例的行为，不代表全部改写正确，也没有证明检索质量提升。输出 JSON 结构验证与语义验收需要分开。

## 后台任务与结果

运行：

```powershell
& 'D:/WorkSoftware/anaconda3/envs/Interview_Copilot/python.exe' -X utf8 -u -m evaluation.mtrag.rewrite_campaign
```

脚本与聊天监控独立，逐条持久化成功缓存。相同命令可以续跑，已完成输入不会重新调用；不确定是否已计费的失败请求不会自动重发。遇到首个失败停止，避免持续消耗额度。

输出目录 `data/evaluation/mtrag/rewrite-v2.1/`：

- `status.json`：当前状态和完成数量。`complete` 才表示全量完成。
- `manifest.json`：冻结提示词、调用参数、输入指纹、完整上下文审计。
- `smoke-review.json`：四个诊断案例的检查结论。
- `campaign.log` / `campaign-error.log`：后台日志。
- `rewritten.jsonl`：全量成功后原子写入的新版改写。
- `comparison.json`：新旧改写与历史对照；全量未完成前可能仍为四条检查结果。
- `summary.json` / `README.md`：全量完成后生成的统计和报告。

此任务仅重新改写，不启动答案生成。后续检索对照需要显式使用 v2 请求身份与该目录的结果，不能直接把它覆盖到使用 v1 身份校验的旧实验中。

## 首轮试运行暴露的问题及修订

最初 v2 在第 59 个唯一请求返回了额外字段，并把个人陈述改成了此前话题模式下的问题；严格校验停止了任务。保留 58 条成功缓存及失败原始响应，没有放宽输出校验，也没有重发同一失败请求。

当前冻结版本为 v2.1：新增非请求陈述保持原样的规则，并按 [DeepSeek JSON Output 官方说明](https://api-docs.deepseek.com/guides/json_mode/) 加入明确 JSON 示例。四条真实诊断输入重新检查通过，11 项离线测试通过。为保证整个新实验使用同一提示词，v2.1 使用新缓存身份，最初试运行的请求不混入最终结果；因此此次开发有额外试运行调用，不能把总费用声称为恰好 1,092 次。

原 v2 试运行记录保留在 data/evaluation/mtrag/rewrite-v2/，最终版本结果位于 data/evaluation/mtrag/rewrite-v2.1/。
