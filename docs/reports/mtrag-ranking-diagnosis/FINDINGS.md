# 本轮结论：原始提示词下的下一项诊断

## 基线与执行

按用户要求停止提示词修改。当前默认入口仍使用最初 v1 提示词，`rewritten.jsonl` 的旧缓存没有被覆盖。已验证旧查询、改写、任务、运行清单的 SHA256 与初始优化实验一致，M3 模型清单指纹也一致。v2/v2.1 仅作为历史实验保留。

本轮读取既有结果、512/1024 分数和本地 tokenizer，没有 LLM 调用，也没有新模型前向推理。

## 1. 全量阶段定位：1,109 题

| 前十没有标注正例的首个阻断位置 | 题数 |
|---|---:|
| BM25 与向量各前50都没找到正例 | 73 |
| 两路并集有正例，但融合前50丢失 | 26 |
| 融合候选有正例，重排后全部掉出前十 | 100 |
| 合计 | 199 |

另外910题至少有一个标注正例进入前十。题目级首个阻断位置与片段对去向不能混算。2,979个题目—正例片段对中，505在召回阶段缺失、149被融合截掉、551在候选中但未进最终前十、1,774进入前十。

## 2. 截断存在，但不能解释大部分正例排序遗漏

只在已有两种长度缓存的659道调参题上，固定原融合前50候选，对比512/1024输入长度。

- 共32,950个候选对，其中6,422个文档被512预算截断。
- 查询自身超过96-token上限的题数：0。
- 1,381个候选正例中，321个被截断。
- 排名在前十以外的332个正例中，84个被截断，248个未截断。
- 输入增到1024后找回9个前十以外正例（9个都曾被截断），同时丢掉4个原前十正例。
- 44题nDCG改善、34题退步、581题不变。
- 八个数据集/领域单元等权nDCG@10：0.529894 → 0.531795，仅增加0.001901。
- 缓存512分数限制到原池后，与历史基线nDCG不同的题数为0。

这里的轻微正向变化不推翻之前参数网格的结论：本轮固定原融合50候选，之前部分长度比较使用不同候选配置；必须同时注明候选池。结果仅是调参集诊断，不能直接将1024设为新默认。

## 3. 人工核对出的具体原因

### 已确认的可见文本缺失：The Office 的结局

`mtrag-human::1c0e5e78f1a16ea2eb2165b6aa31dc61<::>1` 问 Toby 在剧集结局发生了什么。

正例 `822159927_19149-21432-0-2283` 有617 tokens。512输入下，真正提及 series finale、Toby哭泣及Pam安慰他的尾部不可见；1024时可以看到。固定候选池内，正例从第14升到第2，题目nDCG由0.6131升到1.0000。

这确认了一个具体的证据可见性问题。由于其他竞争片段也可能获得更长文本，不能把所有排名变化都归因于该正例自身分数变化。

### 已确认的指标与可用证据不一致：Cloudant字段

`mtrag-human::d5b1e735a040853ed361a3dfde1b8ef0<::>2` 问Cloudant存储JSON是否需要提前定义字段。

- 标注正例 `ibmcld_00526-7-1750` 有481 tokens，没有被截断，排第25（1024时第26）。
- 第1名 `ibmcld_00580-4796-6846` 有479 tokens，也没有被截断。原文明确说明不需要提前定义字段名称、类型、约束和关系，可以写入自行设计的JSON文档。
- 官方ID级nDCG为0，但第1名文本确实直接覆盖问题中的核心需求。

因此这道题不能仅凭零分认定“重排没有找到答案”，也不能通过拉长输入解决。保留官方标签和分数，另行记录标注覆盖疑点。

### 电话案例也需要区分两类问题

`mtragun-human::bb2691f6d0c8596164da4c1f2111c5e4<::>3` 中，标注正例的电话号码在512可见范围之外，1024后正例由第11升到第3。

但原第1名另一个页面已经包含SAH工作人员联系方式及一般服务号码。因此“找回标注正例”和“从无可用证据变成有可用证据”不是同一结论。

## 4. 决策

继续使用v1改写、512输入及原始融合/重排基线。本轮没有修改提示词、生产链路或官方标签。

下一项值得投入的是：对重排阶段100道标注零命中题核对返回文本是否实际上含证据，将真实排序遗漏和标注覆盖问题分开；再对已确认的尾部证据遗漏考虑定向窗口方案。不能仅凭长文本比例或个别改善再次全局增加长度/候选数量。

详细数据见同目录 `stage-audit.json`、`length-audit.json`、`cases.json`。已有数据参与过调参和诊断，本轮不宣称独立验证或整体质量改善。
