# 升级路线与可验收架构

[总报告](README.md) · [面经追问](面经映射.md)

这是审计建议，不是已实施变更，也不自动覆盖项目现有权威架构文档。先与当前领域契约对齐，再在后续升级任务中形成决策记录。保持模块化单体与现有合理的事实模型；不以迁移框架、增加多 Agent 或拆微服务作为目标。

## 目标职责边界

```text
浏览器：用户意图、确认、任务历史、事件投影
  → API：身份、输入契约、接纳、快照读取
  → Application Use Cases：事务边界、状态转移、权限、幂等
  → PostgreSQL：canonical facts / Turn / ToolCall / lease / outbox
  → 调度与执行 Runtime：容量接纳、资源所有权、生命周期
      → Agent Loop：模型决策、计划、上下文
      → Harness：确定性门禁、预算、审批、checkpoint、恢复
      → Adapters：LLM / MCP / HTTP / 文件 / 检索引擎
  → Event Projection：SSE 游标、断流恢复、前端一致终态
```

索引、缓存、事件流是不同目的的派生数据；外部副作用成功与否必须进持久账本。领域事实不能由 UI、Redis 和 Agent 内存各维护一份互相竞争的权威版本。

## G0：建立可信基线与会话安全

**对应 F05/F06/F10/F11。** 冻结当前受审工作区为可重建 commit；统一 lock、镜像和 CI pgvector。修复 prompt 导入与两个场景映射，让完整标准命令一次通过。把六个审计探针转成期望正确行为的回归测试，而不是保留“错误发生即通过”的形式。完成 refresh 原子消费和持久撤销。

**验收产物：** 依赖/数据库版本清单、干净 CI 链接、用户旅程对应的测试、refresh 并发与撤销宕机恢复证据。基础设施必需项不能 skip 后全绿。修复 F401 时先确认模型注册语义，不可机械删除 import。

## G1：统一运行时、容量与资源退出

**对应 F01/F02/F09/F14。** 用一份 ADR 选定 API I/O 模式、worker pool、loop 与客户端归属、Session/事务所有者。按真实进程数建立 DB/Redis/模型并发预算，分离长连接与控制面容量。SSE 不能持有整个流生命周期的 DB 事务。shutdown 按停止接纳→挂起/排空→关闭资源执行。

**验收产物：** 运行时拓扑图、连接预算表、真实 Redis/本地模型兼容服务的并发与取消测试、反复启动退出的资源计数。目标并发由实际产品负载决定；本报告没有凭空设定“支持一万并发”。

## G2：闭合任务、事件与副作用恢复

**对应 F03/F04/F07/F08。** Turn 接纳、排队、运行、等待用户、终止各有清楚时钟；owner/generation 控制续租和终态提交。Outbox fencing 与外部幂等/对账同时设计。SSE 用 snapshot + generation/cursor 恢复。预算耗尽是明确的可续跑状态，不能假装正常完成，也不能丢失已成功副作用。

**验收产物：** 状态转移表和禁止转移、旧 owner 写入拒绝、Redis 中断恢复、worker 被杀/卡住/重投、外部响应丢失与取消竞态测试。对每项副作用回答“谁授权、谁执行、如何确认、未知时怎样处理”。

## G3：取得当前 RAG、上下文、记忆的质量证据

**对应 F12/F13/F15。** 固定当前 pgvector、分词、embedding/reranker、阈值与 generation 契约；维护校准/开发/holdout 分割。补跨租户、删除、代际切换、无答案、表格扫描件、提示注入与来源引用样本。先测 SQL 统计开销，再决定是否重构 BM25。记忆必须支持来源、修订、遗忘与冲突处理，不能只测“写入后能搜索”。

**验收产物：** 当前指纹 release_ready=true 的报告、失败集、消融实验、exact/ANN 比较、检索与回答分层指标，以及实际任务采纳率。所有收益同时报告时延/成本，旧 Milvus 报告仅保留为历史。

## G4：按领域边界整理代码与验证控制面

**对应 F16/F17/F18/F19。** 把巨型协调函数中的纯状态转移、事务用例、I/O adapter、事件投影拆出；先保行为，再迁移调用，避免兼容分支无限堆积。对授权、租户、execution owner、generation 等参数建立类型与静态依赖约束。明确本地受信任插件与托管不可信插件的不同安全边界。

**验收产物：** 每个业务不变量的单一写入口、依赖方向检查、关键流程时序、端到端 trace 与 SLO 仪表盘、空环境 restore 演练。代码整洁以职责、可替换性、事务清晰度和变更影响面衡量，不以文件长度机械评分。

## 产品级用户旅程验收

| 旅程 | 成功定义 | 必须注入的异常 |
|---|---|---|
| 注册、登录、刷新、退出 | 会话状态可解释，旧凭证按承诺失效 | 并发刷新、Redis 写失败/恢复、响应丢失 |
| 提交对话并获得回复 | 唯一持久 Turn，刷新页面后仍见正确结果 | API 重试、长排队、worker 重投、SSE 断连 |
| Agent 执行职业相关写操作 | 授权参数与实际执行一致，副作用有账本 | 审批后篡改、重复投递、租约过期、外部超时 |
| 用户取消或审批挂起 | 取消/挂起及时生效，已发生结果不丢失 | 工具部分完成、worker 迟到、网络失联 |
| 上传、更新、删除知识 | 当前事实与索引一致，可引用且租户隔离 | 解析失败、重复上传、代际切换、删除竞态 |
| 连续长对话与长期记忆 | 关键约束不丢，来源可追，修订/遗忘生效 | 压缩失败、checkpoint 冲突、记忆任务停摆 |
| 备份恢复与重新部署 | 业务事实完整，派生数据可重建 | DB/文件不同时点、正在执行的外部动作 |
| 突发负载与超额预算 | 明确拒绝或排队，其他租户仍可用 | 连接池耗尽、慢模型、慢读者、无限变化工具调用 |

## 每次发布必须能出示的证据包

1. 精确代码、依赖、镜像、数据库扩展和运行参数版本。
2. 完整自动检查与必需数据库测试；不能隐藏收集失败和跳过项。
3. 上述用户旅程与故障场景的 trace、持久状态和前端结果。
4. 当前 RAG/Agent/记忆评测报告、样本来源、切分和失败分布。
5. 实际负载曲线、资源预算、成本、取消/恢复时限与 restore 数据。
6. 已知边界及产品对用户的真实承诺，包含插件信任、审批与未知副作用。

建议每完成一个门槛再进入下一组依赖工作，保留可发布的小步变更。没有对应证据的能力仍标为“待验证”，不提前在简历、演示或产品介绍中宣布成熟。
