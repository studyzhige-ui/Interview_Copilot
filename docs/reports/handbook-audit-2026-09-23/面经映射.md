## 重点追问链：从知识点到可证明的项目回答

### 1. 为什么用异步？async 中执行 SQL 会不会阻塞？

**来源：** [S294](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-33.md#L11)。部分为原题向项目的延伸追问，不声称来源逐字提出了本小节全部问题。

**项目回答：** 实际链路是 async API → 同步 Session → psycopg2；Celery 又是线程内各自 loop。不能回答“用了 async 就高并发”。

**证据/验收：** P3/A1；F01/F02；画清进程、线程、loop、连接池边界，以混合长 SSE/慢 SQL 负载证明。

### 2. Python 的对象共享与锁是否足以保证线程安全？

**来源：** [S294](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-33.md#L11)。部分为原题向项目的延伸追问，不声称来源逐字提出了本小节全部问题。

**项目回答：** LLM 缓存锁保护查找，但连接资源绑定的 loop 仍被共享。GIL 不保护 I/O 生命周期。

**证据/验收：** P3；F02；以两个 loop 访问同一真实客户端的测试回答，不能只讲 GIL。

### 3. SQL 从800ms降到50ms，接口为何仍慢？

**来源：** [S293](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-32.md#L38)。部分为原题向项目的延伸追问，不声称来源逐字提出了本小节全部问题。

**项目回答：** 要分离排队、连接池、检索、重排、模型、工具、持久化和事件推送，项目暂无本次全链分位数。

**证据/验收：** O1/R1/A1；F09/F13/F17；提交带 trace 的端到端分解，不能编造优化收益。

### 4. MySQL 为什么 B+Tree？项目数据库是否同样组织？

**来源：** [S282](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-27.md#L67)、[S293](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-32.md#L38)、[S294](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-33.md#L11)。部分为原题向项目的延伸追问，不声称来源逐字提出了本小节全部问题。

**项目回答：** 解释磁盘页/范围查询和复合索引，再指出 PostgreSQL heap+索引和 MVCC 的不同；本项目不是 InnoDB。

**证据/验收：** D3/R1；提供本项目 EXPLAIN/锁范围/事务边界，MySQL redo+binlog 2PC 作为知识迁移而非实现声明。

### 5. Redis 为什么快，缓存击穿与故障如何处理？

**来源：** [S294](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-33.md#L11)。部分为原题向项目的延伸追问，不声称来源逐字提出了本小节全部问题。

**项目回答：** 项目 Redis 同时支撑缓存、撤销、队列/事件，问题不仅是热 key；阻塞读取占用连接与共故障更贴近本项目。

**证据/验收：** S2/A1；F04/F06/F09；分别验证读取失败、撤销失败和事件恢复，不能统一 fail-open。

### 6. JWT 轮换/退出怎样保证真正失效？

**来源：** [S294](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-33.md#L11)。部分为原题向项目的延伸追问，不声称来源逐字提出了本小节全部问题。

**项目回答：** 已存在撤销表接口，但 refresh check/set 非原子；退出撤销写失败也会成功返回。

**证据/验收：** S1；F05/F06；原子一次消费和宕机恢复后旧 token 无效，是明确验收条件。

### 7. MQ 重投与任务重启如何防重复写？

**来源：** [S287](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-28.md#L11)、[S288](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-29.md#L11)。部分为原题向项目的延伸追问，不声称来源逐字提出了本小节全部问题。

**项目回答：** 有 outbox/工具执行账本，仍必须证明 lease owner、幂等键、未知外部结果各由谁负责。

**证据/验收：** D2/A3；F07；旧 owner 终结 CAS、供应商幂等与对账；不能笼统承诺 exactly-once。

### 8. 长任务排队、挂起和 worker 失联如何区别？

**来源：** [S281](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-27.md#L40)、[S288](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-29.md#L11)。部分为原题向项目的延伸追问，不声称来源逐字提出了本小节全部问题。

**项目回答：** Turn 是持久执行单位，但 pending 当前被60秒失联规则清扫。规划列表不等于调度状态机。

**证据/验收：** A1/A6；F03；暂停消费者后验证排队任务不被错杀，审批挂起可恢复且不占计算 worker。

### 9. Agent Loop 与 Harness 分别是什么？

**来源：** [S281](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-27.md#L40)、[S288](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-29.md#L11)。部分为原题向项目的延伸追问，不声称来源逐字提出了本小节全部问题。

**项目回答：** Loop 负责模型决策迭代；harness 负责授权、工具 schema、执行事实、checkpoint、资源与恢复。项目已实现前半套关键约束。

**证据/验收：** A2/A3/A6；F02/F07/F08/F14；不要把有 ToolExecutor 就称为成熟 harness。

### 10. Agent 完全接管写操作，如何给确定性保护？

**来源：** [S280](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-27.md#L11)、[S288](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-29.md#L11)。部分为原题向项目的延伸追问，不声称来源逐字提出了本小节全部问题。

**项目回答：** 请求 schema → principal → 权限/ask → 参数摘要 → 持久执行账本 → 执行 → 结果投影，门禁必须在执行入口。

**证据/验收：** A3/S3；保留已有预检与审批；加入重放、审批参数变更、重启与迟到结果测试。

### 11. Skill 不遵守限制，是否再写一段高优先级提示？

### 12. 为什么不直接 Workflow？为什么不用多 Agent？

**来源：** [S280](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-27.md#L11)、[S290](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-31.md#L11)、[S295](https://github.com/studyzhige-ui/ai-application-interview-handbook/blob/e5e000c1dbc3546aaea7c2730b78db33f4c7ffb5/market/interviews/batch-33.md#L46)。部分为原题向项目的延伸追问，不声称来源逐字提出了本小节全部问题。

**证据/验收：** A2/A5；用相同任务集比较成功率、延迟、token 和恢复复杂度；没有实验不宣称更优。
